> Linux 进程调度器决定下一个运行的进程。CFS（Completely Fair Scheduler）以虚拟运行时为公平性依据，使用红黑树 O(log n) 选择下一个进程，并提供了可扩展的调度类层次架构。

## 调度类层次

Linux 内核使用模块化调度类架构，每个进程属于一个调度类。调度优先级从高到低：

```
       ┌───────────────────────────┐
       │       stop_sched_class    │ 最高优先级，停止 CPU
       ├───────────────────────────┤
       │     deadline_sched_class  │ SCHED_DEADLINE — EDF 算法
       ├───────────────────────────┤
       │        rt_sched_class     │ SCHED_FIFO / SCHED_RR — 实时线程
       ├───────────────────────────┤
       │       fair_sched_class    │ SCHED_NORMAL (SCHED_OTHER) — CFS 普通进程
       ├───────────────────────────┤
       │       idle_sched_class    │ 最低优先级，空闲进程 PID 0
       └───────────────────────────┘
```

内核在每个 CPU 上运行 `__pick_next_task()` 遍历调度类，高优先级类有进程可运行时低优先级类不会获得 CPU。

## CFS 完全公平调度器

### 核心思想

CFS 模型化的理想 CPU 是 " 完美多任务处理器 "——一个 CPU 同时运行所有进程，每个进程获得 1/n 的 CPU 时间。实际实现中，CFS 通过 **vruntime（虚拟运行时）** 追踪每个进程获得了多少 CPU 时间：

```
vruntime += delta_exec * NICE_0_LOAD / se.load.weight
```

* **delta_exec**: 进程实际执行的物理时间
* **se.load.weight**: 进程权重（由 nice 值映射）
* **NICE_0_LOAD**: nice=0 的权重（1024）

权重越大，vruntime 增长越慢，获得更多 CPU 时间。

### nice 值与权重映射

| nice 值 | 权重 (weight) | 相对 nice=0 的 CPU 占比 |
|---------|---------------|------------------------|
| -20 | 88761 | ~86.6x |
| -10 | 9548 | ~9.3x |
| -5 | 3121 | ~3.0x |
| 0 | 1024 | 1.0x (基准) |
| 5 | 335 | ~0.3x |
| 10 | 110 | ~0.1x |
| 19 | 15 | ~0.015x |

nice 值每差 1，权重变化约 **1.25x**；nice 值每差 5，权重变化约 **3x**。

### 红黑树选择

```
CFS 红黑树 (rbtree):
    key = se.vruntime

            node (vruntime=1000)
           /                \
     node (800)          node (1200)
     /       \            /        \
   (700)    (900)     (1100)     (1300)

  → 最左节点 (min_vruntime) 就是下一个要运行的进程
  → 插入、删除均为 O(log n)
```

* 所有可运行进程的调度实体按 vruntime 作为 key 插入红黑树
* 每次调度选择**最左节点**（vruntime 最小的进程）
* 进程被调度执行后，vruntime 递增，可能被重新插入到树中更靠右的位置
* `min_vruntime` 缓存了当前树的最小值，用于新进程和休眠后唤醒的 vruntime 初始化

### 调度周期与最小粒度

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `sysctl_sched_latency` | 6ms (sysctl) | CFS 调度周期 |
| `sysctl_sched_min_granularity` | 0.75ms | 进程最短执行时间 |
| `sysctl_sched_wakeup_granularity` | 1ms | 唤醒进程的抢占粒度 |

## 进程调度策略

```c
#include <sched.h>

int sched_setscheduler(pid_t pid, int policy, const struct sched_param *param);
int sched_getscheduler(pid_t pid);
```

| 策略宏 | 调度类 | 说明 |
|--------|--------|------|
| `SCHED_NORMAL` (SCHED_OTHER) | fair | 普通分时进程，CFS 调度 |
| `SCHED_BATCH` | fair | 批量进程，降低唤醒抢占倾向 |
| `SCHED_IDLE` | idle | 极低优先级，仅在 CPU 空闲时运行 |
| `SCHED_FIFO` | rt | 先进先出实时进程（1-99 优先级） |
| `SCHED_RR` | rt | 时间片轮转实时进程 |
| `SCHED_DEADLINE` | deadline | 最晚截止时间优先（EDF） |

### 实时调度策略

**SCHED_FIFO**:

* 优先级范围 1-99（数值越大优先级越高）
* 先到先执行，除非被更高优先级抢占或主动让出 (sched_yield)
* 无时间片限制，持续运行直到阻塞或 yield
* 若 FIFO 线程陷入死循环，低优先级线程将**永久饥饿**

**SCHED_RR**:

* 同优先级间时间片轮转（默认 100ms）
* 时间片用完后放到队列末尾
* 同样可抢占低优先级

```c
#include <sched.h>
#include <stdio.h>

int main() {
    struct sched_param param;
    param.sched_priority = 50;  // 优先级 50 (1-99)

    if (sched_setscheduler(0, SCHED_FIFO, &param) == -1) {
        perror("sched_setscheduler (need root?)");
        return 1;
    }

    printf("Set to SCHED_FIFO, priority=50\n");
    // 注意: FIFO 实时线程要小心不要死循环
    return 0;
}
```

> 设置实时调度策略需要 `CAP_SYS_NICE` 特权（通常是 root），或配置 `limits.conf` 中 `rtprio` 限制。

## CPU 亲和性

绑定进程/线程到特定 CPU 核心执行，改善缓存局部性。

```c
#define _GNU_SOURCE
#include <sched.h>
#include <stdio.h>

int main() {
    cpu_set_t cpuset;
    CPU_ZERO(&cpuset);
    CPU_SET(0, &cpuset);   // 绑定到 CPU 0
    CPU_SET(2, &cpuset);   // 同时绑定到 CPU 2

    if (sched_setaffinity(0, sizeof(cpu_set_t), &cpuset) == -1) {
        perror("sched_setaffinity");
        return 1;
    }

    printf("Process pinned to CPUs: 0 and 2\n");

    // 查看当前 CPU 亲和性
    cpu_set_t get;
    CPU_ZERO(&get);
    sched_getaffinity(0, sizeof(cpu_set_t), &get);

    printf("Affinity mask: ");
    for (int i = 0; i < CPU_SETSIZE; i++) {
        if (CPU_ISSET(i, &get)) printf("%d ", i);
    }
    printf("\n");
    return 0;
}
```

### taskset 命令

```bash
# 绑定到 CPU 0-3
taskset -c 0-3 ./myprogram

# 绑定已运行的 PID 到 CPU 0-3
taskset -p -c 0-3 12345

# 查看 PID 的 CPU 亲和性
taskset -p 12345
```

## sched_yield

```c
#include <sched.h>

int sched_yield(void);
```

* 当前进程**主动让出** CPU，放到运行队列末尾
* 对 SCHED_FIFO 实时线程有用（避免同优先级饥饿）
* 对普通 CFS 进程通常不建议使用，可能造成调度抖动

## 内核抢占与 TIF_NEED_RESCHED

内核通过以下机制实现抢占：

1. **TIF_NEED_RESCHED 标志** — 设置在当前进程的 `thread_info->flags`
2. **设置时机**：
   * 定时器中断（scheduler_tick）发现当前进程时间片已用完
   * 唤醒的进程有更高优先级（try_to_wake_up）
   * sched_yield 系统调用
3. **检查时机**：
   * 系统调用返回用户空间前
   * 中断处理程序返回内核空间前
   * 显式调用 `preempt_enable()` 时（内核抢占）
   * 自旋锁释放时

```
      定时器中断
          │
          ▼
    scheduler_tick()
          │
          ▼
  设置 TIF_NEED_RESCHED
          │
          ▼
   中断返回 → 检查标志 → __schedule() → 上下文切换
```

## 调度信息查看

### /proc 文件系统

| 文件 | 说明 |
|------|------|
| `/proc/[pid]/sched` | 进程调度统计（vruntime、等待时间、时间片） |
| `/proc/[pid]/schedstat` | 调度延迟统计 |
| `/proc/sched_debug` | 全局调度器调试信息（需要内核配置 `CONFIG_SCHED_DEBUG`） |
| `/proc/schedstat` | 调度域和调度组统计 |
| `/proc/loadavg` | 系统平均负载 (1/5/15 分钟) |
| `/proc/stat` | CPU 时间统计（user/nice/system/idle/iowait） |

```bash
# 查看某个进程的调度信息
cat /proc/self/sched

# 查看所有 CPU 的运行队列和负载
cat /proc/sched_debug | head -50

# 查看 CPU 时间分布
cat /proc/stat | grep "^cpu"
```

### 调度延迟观察

```bash
# 使用 perf sched 观察调度延迟
perf sched record -- sleep 5
perf sched latency

# 使用 trace-cmd 跟踪调度事件
trace-cmd record -e sched_switch -e sched_wakeup sleep 1
trace-cmd report
```

## NUMA 调度优化

现代多路服务器中，CFS 结合 NUMA 感知策略：

* **调度域 (Scheduling Domain)** — 分层拓扑结构（SMT → Core → LLC → NUMA node → System）
* **负载均衡** — 在调度域内平衡任务分布
* **NUMA 亲和性** — 尽量在分配内存的 NUMA 节点上运行进程
* 使用 `numactl` 控制 NUMA 策略

```bash
# 绑定到 NUMA node 0
numactl --cpunodebind=0 --membind=0 ./myprogram
```
