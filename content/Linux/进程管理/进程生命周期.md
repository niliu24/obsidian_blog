> Linux 进程生命周期以 **task_struct** 为进程描述符，通过 fork() 创建、execve() 加载、exit() 终止、wait() 回收，形成完整的 " 生老病死 " 闭环。

## task_struct —— 进程描述符

内核使用 `task_struct` 结构体表示每个进程，定义在 `<include/linux/sched.h>`。关键字段如下：

| 字段 | 说明 |
|------|------|
| `pid_t pid` | 进程唯一标识符 (PID) |
| `volatile long state` | 进程当前状态 |
| `struct mm_struct *mm` | 进程地址空间（页表、VMA 等） |
| `struct files_struct *files` | 打开的文件描述符表 |
| `struct signal_struct *signal` | 信号处理与挂起信号 |
| `struct task_struct __rcu *parent` | 父进程 task_struct 指针 |
| `struct list_head children` | 子进程链表 |
| `struct list_head sibling` | 兄弟进程链表 |
| `struct thread_struct thread` | CPU 上下文（寄存器、栈指针） |
| `unsigned int flags` | 进程标志（如 PF_KTHREAD） |
| `int prio, static_prio, normal_prio` | 调度优先级 |
| `struct sched_entity se` | CFS 调度实体 |

内核维护一个双向循环链表 `tasks` 链接着所有进程的 `task_struct`，通过 `for_each_process(p)` 宏遍历。

## 进程状态

Linux 进程有五种基本状态，在 `task_struct->state` 中记录：

```
                    ┌─────────────┐
                    │  fork()     │
                    │  创建       │
                    └──────┬──────┘
                           ↓
              ┌──────────────────────┐
              │   TASK_RUNNING       │◄──────────────────────────┐
              │   (就绪/运行中)       │                            │
              └──────┬───────────────┘                            │
                     │                                            │
          调度抢占    │   等待资源                                  │
          ┌──────────┘           │                                │
          ↓                      ↓                                │
  ┌───────────────┐   ┌──────────────────────┐                  │
  │ TASK_RUNNING  │   │  TASK_INTERRUPTIBLE  │                  │
  │ (重新获得CPU) │   │  (可中断睡眠)         │                  │
  └───────────────┘   └──────────┬───────────┘                  │
                                 │                              │
                                 │ 等待 I/O 完成                 │
                                 │ (不可被信号打断)               │
                                 ↓                              │
                    ┌──────────────────────┐                    │
                    │ TASK_UNINTERRUPTIBLE │                    │
                    │ (不可中断睡眠)        │                    │
                    └──────────┬───────────┘                    │
                               │                                │
                    资源就绪/信号到达                            │
                               │                                │
                               └────────────────────────────────┘
                     
                     (从运行态)
                         │
                         │ exit() / 信号
                         ↓
              ┌──────────────────────┐
              │    EXIT_ZOMBIE       │
              │    (僵尸进程)         │
              └──────────┬───────────┘
                         │
                         │ parent 调用 wait() / waitpid()
                         ↓
              ┌──────────────────────┐
              │    EXIT_DEAD         │
              │    (进程销毁)         │
              └──────────────────────┘
```

| 状态宏 | 值 | 说明 |
|--------|-----|------|
| `TASK_RUNNING` | 0 | 就绪态（等待 CPU）或运行中 |
| `TASK_INTERRUPTIBLE` | 1 | 可中断睡眠，等待资源，可被信号唤醒 |
| `TASK_UNINTERRUPTIBLE` | 2 | 不可中断睡眠，等待资源（如 D 状态磁盘 I/O） |
| `TASK_STOPPED` | 4 | 暂停执行，收到 SIGSTOP/SIGTSTP 等 |
| `TASK_TRACED` | 8 | 被 ptrace 跟踪暂停 |
| `EXIT_ZOMBIE` | 16 | 已终止但未被父进程回收 |
| `EXIT_DEAD` | 32 | 最终销毁状态 |

> **D 状态进程**：`TASK_UNINTERRUPTIBLE` 通常出现在等待磁盘 I/O 完成时，进程不能被信号杀死（包括 SIGKILL），只能等待 I/O 完成后由内核唤醒。

## fork() —— 进程创建

`fork()` 创建当前进程的副本。在父进程中返回子进程 PID，在子进程中返回 0。

### Copy-On-Write (COW)

现代 Linux 中 `fork()` 不立即复制所有内存页，而是采用 **写时拷贝** 优化：

1. fork 后父子进程共享所有内存页，页表标记为**只读**
2. 任一进程尝试写入时触发**缺页异常**
3. 内核分配新页帧，复制内容，更新页表
4. 未写入的页继续共享

这种机制使得 fork 调用轻量且高效，尤其适合 `fork + exec` 模式。

### 代码示例

```c
#include <unistd.h>
#include <stdio.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        // 子进程
        printf("Child: PID=%d, Parent PID=%d\n", getpid(), getppid());
        // 替换为 /bin/ls
        execl("/bin/ls", "ls", "-l", NULL);
        // exec 出错才会执行到这里
        perror("exec failed");
        return 1;
    } else if (pid > 0) {
        // 父进程
        printf("Parent: created child PID=%d\n", pid);
        wait(NULL);  // 等待子进程结束，避免僵尸进程
        printf("Parent: child terminated\n");
    } else {
        perror("fork failed");
        return 1;
    }
    return 0;
}
```

### vfork()

`vfork()` 是更古老的创建方式——子进程**借用**父进程地址空间运行，父进程阻塞直到子进程 exec 或 exit。现代 Linux 中 COW 已大幅降低 vfork 的需求，但某些场景（无内存压力的 exec 前准备）仍有使用。

## execve() —— 程序装载

```c
#include <unistd.h>

int execve(const char *pathname, char *const argv[], char *const envp[]);
```

`execve()` 将当前进程替换为指定 ELF 可执行文件：

1. **解析 ELF 头部** — 验证魔数 (ELF Magic)，识别架构
2. **加载器选择** — 由 `struct linux_binfmt` 注册链决定（ELF binfmt 常用）
3. **清空地址空间** — 释放原进程的 mm_struct，建立新 VMA
4. **映射 ELF Segment** — 将 PT_LOAD 段映射到虚拟地址空间
5. **初始化栈和寄存器** — 传参（argc/argv）、环境变量 (envp)、辅助向量 (auxv)
6. **设置入口点** — 若为动态链接 ELF，入口为 `/lib/ld-linux.so.2`，由它加载共享库后跳转到 `_start`
7. **切换执行** — `start_thread()` 设置新 PC 和 SP

> `execve()` 成功后不返回——旧的进程镜像完全消失。

## exit() —— 进程终止

```c
#include <stdlib.h>

void exit(int status);       // 标准库函数，调用 exit_group 系统调用
void _exit(int status);      // 直接触发 exit 系统调用
```

进程终止步骤：

1. 调用 `exit_notify()` — 设置进程状态为 `EXIT_ZOMBIE`
2. 释放文件描述符、内存页、信号处理等资源（task_struct 本身保留）
3. 发送 SIGCHLD 给父进程
4. 父进程通过 `wait()` / `waitpid()` 读取退出状态后，内核回收 task_struct

## wait() —— 进程回收

```c
#include <sys/wait.h>

pid_t wait(int *status);                         // 等待任意子进程
pid_t waitpid(pid_t pid, int *status, int options);  // 等待指定子进程
```

`wait` 宏：

| 宏 | 说明 |
|----|------|
| `WIFEXITED(status)` | 子进程正常退出 |
| `WEXITSTATUS(status)` | 获取退出码 |
| `WIFSIGNALED(status)` | 被信号终止 |
| `WTERMSIG(status)` | 获取终止信号编号 |
| `WIFSTOPPED(status)` | 子进程暂停 |
| `WSTOPSIG(status)` | 获取暂停信号编号 |

## 僵尸进程问题

### 产生原因

子进程先于父进程退出，父进程未调用 `wait()`，子进程的 task_struct 无法被内核回收。

```
      父进程
     ┌──────┐
     │ fork │──── 创建子进程，未 wait
     └──┬───┘
        │                     子进程 exit()
        │                    ┌────────┐
        │                    │ ZOMBIE │──── task_struct 残留在内核中
        │                    └────────┘
        │  (父进程继续运行，不 wait)
        ▼
    [内存泄漏] — 僵尸进程越多，内核 slab 占用越大
```

### 危害

* 内核进程表 slot 被占用（每僵尸消耗 `task_struct` 内存）
* PID 耗尽风险（`pid_max` 默认 32768）
* 最终 `fork()` 失败报 `-EAGAIN`

### 防范方法

1. **显式 wait** — 父进程 `waitpid()` 回收子进程
2. **信号处理** — 忽略 `SIGCHLD`，内核自动回收（`signal(SIGCHLD, SIG_IGN)`）
3. **二次 fork** — 子进程再调一次 fork，孙进程由 init 收养（会自动 wait）
4. **双进程模式** — 独立监控进程专门 wait

```c
// 使用 SIGCHLD 忽略自动回收
#include <signal.h>

int main() {
    signal(SIGCHLD, SIG_IGN);  // 子进程结束自动回收，不产生僵尸
    pid_t pid = fork();
    if (pid == 0) {
        printf("Child running...\n");
        _exit(0);
    }
    pause();  // 父进程挂起
    return 0;
}
```

### 孤儿进程

父进程先退出，子进程成为孤儿，由 **init（PID 1）** 收养并自动 wait。
