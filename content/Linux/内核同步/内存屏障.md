> 内存屏障（Memory Barrier）强制 CPU 和编译器不跨越屏障重排访存指令。在多核系统和弱内存模型架构（ARM、PowerPC）上，内存屏障是构建正确同步原语的基础。

## 基本 API

```c
#include <asm/barrier.h>

smp_mb();    // 通用内存屏障 (保证所有加载/存储的全局顺序)
smp_rmb();   // 读内存屏障 (保证之前读操作在之后读操作之前完成)
smp_wmb();   // 写内存屏障 (保证之前写操作在之后写操作之前完成)

// 在 x86 上:
//   smp_mb() → mfence 或 LOCK 前缀
//   smp_rmb() → 编译器屏障 (x86 硬件保证读顺序)
//   smp_wmb() → 编译器屏障 (x86 硬件保证写顺序, 除 WC 内存外)
```

## 常见使用场景

| 场景 | 需要的屏障 | 说明 |
|------|-----------|------|
| 写数据 → 写标志 | `smp_wmb()` | 确保数据先于标志可见 |
| 读标志 → 读数据 | `smp_rmb()` | 确保读到标志后再读数据 |
| 生产者 - 消费者 | `smp_mb()` | 通用全屏障 |
| RCU 指针更新 | `rcu_assign_pointer()` 内含屏障 | 隐含内存屏障 |

## 示例：无锁环形缓冲区

```c
// 生产者: 写入数据后更新写指针
buffer[write_idx] = data;
smp_wmb();                    // 确保数据写入在指针更新前对所有 CPU 可见
WRITE_ONCE(write_idx, next);

// 消费者: 读取指针后读取数据
unsigned int idx = READ_ONCE(write_idx);
smp_rmb();                    // 确保读到的指针值之后读取的数据是最新的
data = buffer[idx];
```

## x86 vs ARM 内存模型差异

| 特性 | x86 (TSO) | ARM (弱内存模型) |
|------|-----------|----------------|
| 写 - 写重排 | 不重排 | 可能重排 |
| 读 - 读重排 | 不重排 | 可能重排 |
| 读 - 写重排 | 不重排 | 可能重排 |
| 写 - 读重排 | 可能重排 (Store Buffer) | 可能重排 |
| smp_wmb() 成本 | 仅编译器屏障 | 硬件屏障指令 (DMB) |
| smp_rmb() 成本 | 仅编译器屏障 | 硬件屏障指令 (DMB) |

> 在 x86 上，`smp_wmb()` 和 `smp_rmb()` 是廉价的（仅编译器屏障），但在 ARM 上它们会生成 DMB 指令，开销更高。这意味着在 x86 上能 " 侥幸 " 工作的无锁代码在 ARM 上可能失败。
