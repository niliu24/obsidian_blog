> Linux 文件系统是内核 VFS（Virtual File Switch）层之下的具体实现，涵盖磁盘文件系统、伪文件系统和内存文件系统，共同向用户空间提供统一的文件访问接口。其设计遵循 " 一切皆文件 "（Everything is a File）哲学，将普通文件、目录、设备、套接字、管道等资源抽象为文件描述符，赋予统一的读写语义。

## 核心职责

| 职责 | 说明 |
|------|------|
| 统一抽象 | 通过 VFS 层屏蔽具体文件系统差异，向上提供 `open`/`read`/`write`/`close` 等 POSIX 接口 |
| 磁盘布局 | 管理磁盘上的超级块、inode 表、数据块 bitmap、目录项等结构 |
| 数据持久化 | 保证写入数据最终落盘，通过 journal/journalling 机制避免崩溃后元数据不一致 |
| 缓存加速 | 利用 Page Cache 缓存最近访问的文件数据，显著提升 I/O 性能 |
| 权限与安全 | 基于 inode 的权限位 (rwx) 和 ACL，配合 LSM 实现访问控制 |
| 伪文件系统 | procfs、sysfs、cgroupfs 等向用户空间暴露内核状态和控制接口 |

## 文件系统类型对比

| 文件系统 | 类型 | 日志 | 最大文件 | 最大卷 | 适用场景 |
|----------|------|------|----------|--------|----------|
| ext4 | 磁盘 | metadata journal / data journal | 16 TB | 1 EB | 通用默认，兼容性好 |
| xfs | 磁盘 | metadata journal (B+tree) | 8 EB | 8 EB | 大文件、高并发、企业级存储 |
| btrfs | 磁盘 | copy-on-write (checksum) | 16 EB | 16 EB | 快照、压缩、自修复 |
| tmpfs | 内存 | 无（掉电丢失） | 取决于 RAM+Swap | 取决于 RAM+Swap | /tmp、共享内存 |
| procfs | 伪 | 无 | — | — | 进程和内核信息 |
| sysfs | 伪 | 无 | — | — | 设备和驱动模型 |
| squashfs | 磁盘（只读） | 无 | 取决于实现 | 取决于实现 | 嵌入式、容器镜像 |

## 整体架构

```
用户进程 (syscall: open/read/write/close)
    │
    ▼
VFS (虚拟文件系统交换层)
    │  ┌──────────────┬──────────────┬──────────────┐
    │  │  super_block │    inode     │    dentry    │    file
    │  └──────────────┴──────────────┴──────────────┘
    │
    ▼
具体文件系统 (ext4/xfs/btrfs/tmpfs/procfs/sysfs)
    │
    ▼
通用块层 (Generic Block Layer / IO Scheduler)
    │
    ▼
块设备驱动 (Block Device Driver)
    │
    ▼
磁盘 / SSD / NVMe
```
