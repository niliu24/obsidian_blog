> 块设备以固定大小的块（通常 512B/4KB）为单位进行随机访问，数据通过内核 Page Cache 缓冲。与字符设备不同，块设备面向存储类硬件（磁盘、SSD），有自己的请求队列和 I/O 调度机制。

## 块设备 vs 字符设备

| 特性 | 字符设备 | 块设备 |
|------|----------|--------|
| 访问方式 | 字节流 (stream) | 块 (block, 通常 512B/4KB) |
| 随机访问 | 支持 seek | 天然支持 (按块寻址) |
| 缓冲 | 无内核缓冲 | 通过 Page Cache + 请求队列 |
| 主要接口 | `file_operations` | `block_device_operations` |
| 示例 | 串口、GPIO | 硬盘、SSD |

## 核心数据结构

```c
// 块设备操作接口
struct block_device_operations {
    int (*open)(struct block_device *, fmode_t);
    void (*release)(struct gendisk *, fmode_t);
    int (*ioctl)(struct block_device *, fmode_t, unsigned, unsigned long);
    int (*direct_access)(struct block_device *, sector_t, void **, unsigned long *);
    struct module *owner;
};

// 通用磁盘描述
struct gendisk {
    int major;                          // 主设备号
    int first_minor;                    // 起始次设备号
    int minors;                         // 次设备号数量
    char disk_name[DISK_NAME_LEN];      // 名称 (如 "sda")
    struct block_device_operations *fops;
    struct request_queue *queue;        // 请求队列
    void *private_data;
};
```

## 请求队列与 I/O 调度

块设备驱动的核心是**请求队列**（`request_queue`），负责合并、排序和调度 I/O 请求：

```
用户空间 I/O (read/write)
    → VFS → Page Cache
        → submit_bio() → 通用块层
            → I/O 调度器 (mq-deadline/kyber/bfq)
                → 请求队列 → 驱动回调
                    → 硬件设备
```
