> 每个系统调用有唯一的数字编号。内核通过 `sys_call_table` 数组根据编号查找对应的处理函数。x86_64 的系统调用表定义在 `arch/x86/entry/syscalls/syscall_64.tbl` 中。

## 查看系统调用表

```bash
# x86_64 系统调用号头文件
cat /usr/include/asm/unistd_64.h

# 输出片段 (Ubuntu):
# #define __NR_read 0
# #define __NR_write 1
# #define __NR_open 2
# #define __NR_close 3
# #define __NR_getpid 39
# #define __NR_fork 57
# #define __NR_execve 59
# #define __NR_exit 60
# #define __NR_clone 56
```

## 常用系统调用号 (x86_64)

| 编号 | 名称 | 函数 | 用途 |
|------|------|------|------|
| 0 | read | `sys_read` | 从文件描述符读取 |
| 1 | write | `sys_write` | 写入文件描述符 |
| 2 | open | `sys_open` | 打开文件 |
| 3 | close | `sys_close` | 关闭文件描述符 |
| 9 | mmap | `sys_mmap` | 内存映射 |
| 39 | getpid | `sys_getpid` | 获取进程 PID |
| 56 | clone | `sys_clone` | 创建子进程 (线程) |
| 57 | fork | `sys_fork` | 创建子进程 |
| 59 | execve | `sys_execve` | 执行新程序 |
| 60 | exit | `sys_exit` | 退出进程 |
| 63 | uname | `sys_newuname` | 获取系统信息 |

## sys_call_table

内核通过 `sys_call_table` 数组将系统调用号映射到处理函数：

```c
// 简化的 sys_call_table 概念 (实际定义在 arch/x86/entry/syscall_64.c)
typedef long (*sys_call_ptr_t)(unsigned long, unsigned long, unsigned long,
                                unsigned long, unsigned long, unsigned long);

extern sys_call_ptr_t sys_call_table[];

// 调度时: sys_call_table[rax](rdi, rsi, rdx, r10, r8, r9)
```

系统调用号在整个内核版本中是稳定的（不轻易改变），以保证二进制兼容性。
