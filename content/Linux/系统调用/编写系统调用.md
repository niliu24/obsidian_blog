> 向 Linux 内核添加自定义系统调用需要修改系统调用表、编写处理函数并声明原型。虽然这在生产环境中极少使用（应优先使用 `/proc`、`/sys`、`ioctl` 等标准接口），但理解其流程有助于深入理解系统调用机制。

## 步骤 1: 添加系统调用号

编辑 `arch/x86/entry/syscalls/syscall_64.tbl`，在末尾添加：

```
450     common  hello_world     sys_hello_world
```

格式说明:

| 字段 | 含义 |
|------|------|
| 450 | 系统调用号 (选择未使用的编号) |
| common | ABI 类型 (common = x86_64 通用, 64 = x32) |
| hello_world | 系统调用名称 |
| sys_hello_world | 内核函数名 |

## 步骤 2: 编写处理函数

创建 `kernel/hello.c`:

```c
#include <linux/kernel.h>
#include <linux/syscalls.h>
#include <linux/uaccess.h>
#include <linux/string.h>

// SYSCALL_DEFINE0 = 0 个参数
// SYSCALL_DEFINE1 = 1 个参数，以此类推

SYSCALL_DEFINE1(hello_world, char __user *, buf)
{
    const char *msg = "Hello from kernel!\n";
    size_t len = strlen(msg);

    if (!buf)
        return -EINVAL;

    if (copy_to_user(buf, msg, len))
        return -EFAULT;

    pr_info("hello_world syscall called\n");
    return len; // 返回写入的字节数
}
```

### SYSCALL_DEFINE 宏

| 宏 | 参数个数 | 示例 |
|----|---------|------|
| `SYSCALL_DEFINE0()` | 0 | `SYSCALL_DEFINE0(getpid)` |
| `SYSCALL_DEFINE1()` | 1 | `SYSCALL_DEFINE1(exit, int, error_code)` |
| `SYSCALL_DEFINE2()` | 2 | `SYSCALL_DEFINE2(open, const char, *, filename, int, flags)` |
| `SYSCALL_DEFINE3()` | 3 | `SYSCALL_DEFINE3(read, unsigned int, fd, char *, buf, size_t, count)` |
| `SYSCALL_DEFINE6()` | 6 | 最常用的完整参数版本 |

## 步骤 3: 添加到 Makefile

编辑 `kernel/Makefile`:

```makefile
obj-y += hello.o
```

## 步骤 4: 声明系统调用原型

编辑 `include/linux/syscalls.h`:

```c
asmlinkage long sys_hello_world(char __user *buf);
```

## 步骤 5: 编译内核并测试

```c
// 用户空间测试程序
#define _GNU_SOURCE
#include <unistd.h>
#include <sys/syscall.h>
#include <stdio.h>
#include <string.h>

#ifndef SYS_hello_world
#define SYS_hello_world 450
#endif

int main()
{
    char buf[256] = {0};

    long ret = syscall(SYS_hello_world, buf);
    if (ret < 0) {
        perror("hello_world");
        return 1;
    }

    printf("Kernel says: %s", buf);
    printf("Returned %ld bytes\n", ret);
    return 0;
}
```

## 安全注意事项

- 所有用户空间指针必须通过 `copy_from_user()`/`copy_to_user()` 访问
- 必须严格检查参数有效性（指针非空、缓冲区大小、权限等）
- 新系统调用号是全局唯一的，错误的分配会导致严重问题
- 在生产环境中，优先使用 `ioctl`、`sysfs`、`procfs`、`netlink` 等已有接口
