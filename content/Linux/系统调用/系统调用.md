> 系统调用是用户空间程序进入内核的唯一入口。Linux 提供了约 450 个系统调用（x86_64），涵盖文件操作、进程控制、网络通信等核心功能。理解系统调用机制对于系统编程、性能优化和安全分析至关重要。

## 核心概念

| 概念 | 说明 |
|------|------|
| 系统调用号 | 每个系统调用有唯一的数字编号 |
| 调用约定 | 参数通过寄存器传递，返回值通过 rax |
| 上下文切换 | 用户态 → 内核态的完整切换过程 |
| 返回值 | 0 表示成功，负数表示错误码（-errno） |
| glibc 封装 | 大多数 syscall 通过 glibc 提供的库函数调用 |

## 整体架构

```
用户程序 (libc / 直接 syscall)
    │
    ▼
系统调用入口 (syscall/sysenter/int 0x80)
    │
    ▼
entry_SYSCALL_64 (x86_64 汇编入口)
    │  切换到内核栈、保存寄存器
    ▼
do_syscall_64()
    │  通过 sys_call_table[rax] 查找处理函数
    ▼
具体系统调用处理函数 (如 sys_read / sys_getpid)
    │  在内核空间执行功能
    ▼
返回用户空间
    │  恢复寄存器、sysret 回到用户态
    ▼
用户程序继续执行
```

## 系统调用号

每个系统调用有唯一的数字编号。查看系统的 syscall 表：

```bash
# x86_64 系统调用号头文件
cat /usr/include/asm/unistd_64.h

# 输出片段 (Ubuntu):
# #define __NR_read 0
# #define __NR_write 1
# #define __NR_open 2
# #define __NR_close 3
# #define __NR_getpid 39
# #define __NR_fork 57
# #define __NR_execve 59
# #define __NR_exit 60
# #define __NR_clone 56
```

常用系统调用号（x86_64）：

| 编号 | 名称 | 函数 | 用途 |
|------|------|------|------|
| 0 | read | `sys_read` | 从文件描述符读取 |
| 1 | write | `sys_write` | 写入文件描述符 |
| 2 | open | `sys_open` | 打开文件 |
| 3 | close | `sys_close` | 关闭文件描述符 |
| 9 | mmap | `sys_mmap` | 内存映射 |
| 39 | getpid | `sys_getpid` | 获取进程 PID |
| 56 | clone | `sys_clone` | 创建子进程（线程） |
| 57 | fork | `sys_fork` | 创建子进程 |
| 59 | execve | `sys_execve` | 执行新程序 |
| 60 | exit | `sys_exit` | 退出进程 |
| 63 | uname | `sys_newuname` | 获取系统信息 |

## 调用约定

### x86_64 (syscall 指令)

| 寄存器 | 用途 |
|--------|------|
| `rax` | 系统调用号 |
| `rdi` | 第 1 个参数 |
| `rsi` | 第 2 个参数 |
| `rdx` | 第 3 个参数 |
| `r10` | 第 4 个参数（注意：不是 rcx） |
| `r8` | 第 5 个参数 |
| `r9` | 第 6 个参数 |
| 返回值 | `rax`（0 成功，负值 = -errno） |

### x86 (int 0x80 传统方式)

| 寄存器 | 用途 |
|--------|------|
| `eax` | 系统调用号 |
| `ebx` | 第 1 个参数 |
| `ecx` | 第 2 个参数 |
| `edx` | 第 3 个参数 |
| `esi` | 第 4 个参数 |
| `edi` | 第 5 个参数 |
| 返回值 | `eax` |

## 调用机制演进

| 机制 | 架构 | 速度 | 备注 |
|------|------|------|------|
| `int 0x80` | x86 (32-bit) | 慢 | 传统中断门方式，需查 IDT |
| `sysenter/sysexit` | x86 (32-bit) | 快 | Intel 引入的快速系统调用 |
| `syscall/sysret` | x86_64 | 最快 | AMD 设计，Intel 后续支持 |

### int 0x80 (传统方式)

```
用户态执行 int 0x80
    → CPU 从 IDT 查找 0x80 号门描述符
    → 切换到内核栈 (TSS 中读取)
    → 保存 CS:EIP/SS:ESP 到内核栈
    → 跳转到 entry_INT80_32
    → 在 sys_call_table 中查找处理函数
    → 执行完毕后 iret 返回用户态
```

### syscall (现代 x86_64)

```
用户态执行 syscall 指令
    → CPU 从 MSR 中读取:
       LSTAR     → 内核入口地址
       STAR      → 代码段选择子
       SF_MASK   → RFLAGS 屏蔽掩码
    → RFLAGS 存入 R11, 返回地址存入 RCX
    → 切换到内核栈 (IST 或 per-CPU 栈)
    → 跳转到 entry_SYSCALL_64
    → 执行系统调用
    → sysret 返回: RCX → RIP, R11 → RFLAGS
```

## 直接调用 syscall 示例

通过 `syscall()` 库函数或内联汇编直接调用系统调用。

### 使用 syscall() 函数 (推荐)

```c
#include <unistd.h>
#include <sys/syscall.h>
#include <stdio.h>
#include <errno.h>

int main()
{
    // 直接调用 SYS_getpid (系统调用号 39)
    pid_t pid = syscall(SYS_getpid);
    printf("PID: %d\n", pid);

    // 直接调用 SYS_write (系统调用号 1)
    const char *msg = "Hello via syscall!\n";
    syscall(SYS_write, 1, msg, 19);

    // 错误处理: 返回 -1 并设置 errno
    long ret = syscall(99999); // 不存在的 syscall
    if (ret == -1) {
        printf("Error: %s\n", strerror(errno));
    }

    return 0;
}
```

### 使用内联汇编 (x86_64)

```c
#include <unistd.h>

static inline long my_getpid(void)
{
    long ret;

    __asm__ volatile (
        "mov $39, %%rax\n"    // syscall 号: SYS_getpid
        "syscall\n"           // 调用 syscall 指令
        : "=a" (ret)          // 输出: rax → ret
        :
        : "rcx", "r11",       // syscall 会修改 rcx, r11
          "memory"
    );

    return ret;
}

int main()
{
    printf("PID: %ld\n", my_getpid());
    return 0;
}
```

## VDSO (Virtual Dynamic Shared Object)

VDSO 是内核映射到每个用户进程地址空间的一小段代码，使得某些系统调用无需陷入内核即可完成。

| 函数 | VDSO 加速 | 说明 |
|------|-----------|------|
| `gettimeofday()` | ✅ 通过 rdtsc 读取时间，无 syscall | 最常用 VDSO 场景 |
| `clock_gettime()` | ✅ 通过 VDSO 实现 | |
| `time()` | ✅ | |
| `getcpu()` | ✅ 读取当前 CPU 编号 | |

```bash
# 查看 VDSO 在进程中的映射
cat /proc/self/maps | grep vdso
# 输出: 7ffe9d5b4000-7ffe9d5b6000 r-xp 00000000 ... [vdso]
```

vsyscall 是 VDSO 的前身，映射在固定地址 `0xffffffffff600000`，现已逐步被 VDSO 取代。

## 编写自定义系统调用

下面演示如何在内核中添加一个新的系统调用 `hello_world`。

### 1. 添加系统调用号

编辑 `arch/x86/entry/syscalls/syscall_64.tbl`，在末尾添加：

```
450     common  hello_world     sys_hello_world
```

### 2. 编写处理函数

创建 `kernel/hello.c`：

```c
#include <linux/kernel.h>
#include <linux/syscalls.h>
#include <linux/uaccess.h>
#include <linux/string.h>

// 使用 SYSCALL_DEFINE 宏定义
// SYSCALL_DEFINE0  = 0 个参数
// SYSCALL_DEFINE1  = 1 个参数，以此类推

SYSCALL_DEFINE1(hello_world, char __user *, buf)
{
    const char *msg = "Hello from kernel!\n";
    size_t len = strlen(msg);

    if (!buf)
        return -EINVAL;

    if (copy_to_user(buf, msg, len))
        return -EFAULT;

    pr_info("hello_world syscall called\n");
    return len; // 返回写入的字节数
}
```

### 3. 添加到 Makefile

编辑 `kernel/Makefile`：

```makefile
obj-y += hello.o
```

### 4. 声明系统调用原型

编辑 `include/linux/syscalls.h`：

```c
asmlinkage long sys_hello_world(char __user *buf);
```

### 5. 编译内核并测试

```c
// 用户空间测试程序
#define _GNU_SOURCE
#include <unistd.h>
#include <sys/syscall.h>
#include <stdio.h>
#include <string.h>

#ifndef SYS_hello_world
#define SYS_hello_world 450
#endif

int main()
{
    char buf[256] = {0};

    long ret = syscall(SYS_hello_world, buf);
    if (ret < 0) {
        perror("hello_world");
        return 1;
    }

    printf("Kernel says: %s", buf);
    printf("Returned %ld bytes\n", ret);
    return 0;
}
```

## Strace 跟踪系统调用

`strace` 通过 `ptrace` 系统调用跟踪目标进程的所有系统调用。

```bash
# 跟踪命令
strace ls
strace -e open,read,write ls       # 只跟踪特定系统调用
strace -p 1234                     # 附加到运行中进程
strace -c ls                       # 统计系统调用次数和时间
strace -f ls                       # 跟踪子进程 (fork)
```

### strace 输出示例

```
$ strace -e trace=open,read,write ls ~/
open("/home/user/", O_RDONLY|O_NONBLOCK|O_DIRECTORY|O_CLOEXEC) = 3
getdents64(3, 0x7fff..., 32768)     = 520
getdents64(3, 0x7fff..., 32768)     = 0
close(3)                            = 0
write(1, "Documents\nDownloads\n", 20) = 20
```

每一行格式：

```
系统调用名称(参数...) = 返回值
```

| 字段 | 含义 | 示例 |
|------|------|------|
| `open` | 系统调用名称 | 也可能是 read/write/ioctl |
| `/home/user/` | 字符串参数 | 文件路径 |
| `O_RDONLY` | 标志位参数 | 内核展开为符号名 |
| `= 3` | 返回值 | 文件描述符、字节数或 -1 (错误) |
| `= 520` | 有效返回值 | 读取的字节数 |

### ptrace 基本原理

```c
// strace 的内部机制大致如下:
ptrace(PTRACE_TRACEME, 0, 0, 0);   // 被跟踪进程: 告诉内核将被跟踪
ptrace(PTRACE_ATTACH, pid, 0, 0);  // 跟踪者: 附加到目标进程

while (1) {
    int status;
    waitpid(pid, &status, 0);       // 等待被跟踪进程停止
    // 读取系统调用号和参数 (通过 PTRACE_PEEKUSER)
    // 打印系统调用信息
    ptrace(PTRACE_SYSCALL, pid, 0, 0); // 继续运行直到下一个 syscall
}
```

## glibc 封装 vs 裸 syscall

```c
// glibc 封装 (推荐)
#include <unistd.h>
pid_t pid = getpid();  // 内部调用 syscall(SYS_getpid)

// 裸系统调用 (底层)
#include <sys/syscall.h>
pid_t pid = syscall(SYS_getpid);
```

绝大多数时候应使用 glibc 封装，原因：

| 原因 | 说明 |
|------|------|
| 错误处理 | glibc 自动将内核返回的负值转为 `errno` |
| 缓存 | `getpid()` 在 glibc 中有缓存优化 |
| pthread 集成 | `fork()/clone()` 等与线程库正确协作 |
| VDSO | `gettimeofday()` 通过 VDSO 无需陷入内核 |
| 兼容性 | glibc 处理不同内核版本的差异 |

何时需要直接 `syscall()`：

* 新系统调用尚未被 glibc 封装
* 需要绕过 glibc 的缓存（如强制刷新 pid）
* 编写与 libc 无关的低级代码
