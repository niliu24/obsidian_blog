> 缺页异常 (Page Fault) 是 MMU 在地址转换时因 PTE 的 Present 位为 0 而触发的异常。Linux 通过它实现 Demand Paging、Swap、Copy-on-Write、文件映射延迟加载等核心机制。缺页处理路径是内存管理系统中延迟分配和惰性求值的核心实现。

## 缺页类型

| 类型 | 触发条件 | 典型场景 |
|------|----------|----------|
| **Minor Fault** (软缺页) | 页在物理内存中但未建立映射 | COW、共享匿名页、已 Page Cache 缓存的读 |
| **Major Fault** (硬缺页) | 页不在物理内存中，需从磁盘读取 | 程序首次执行加载代码段、Swap 换入 |
| **Invalid Fault** (非法访问) | 访问非法地址或权限不匹配 | 空指针解引用、越界访问 → SIGSEGV |

## 缺页处理总流程

缺页异常入口在 `arch/x86/mm/fault.c`，核心处理路径如下：

```
缺页异常 (Page Fault Handler)
    │
    ▼
do_page_fault(regs, error_code, address)
    │  解析 error_code: 读/写/执行? 用户态/内核态? 保护违例? 缺页?
    │
    ├─ address 在用户空间? ──→ handle_mm_fault(vma, address, flags)
    │                            │
    │                            ├─ PTE 不存在 (匿名页)
    │                            │   └─ do_anonymous_page()
    │                            │
    │                            ├─ PTE 不存在 (文件映射)
    │                            │   └─ do_fault() → filemap_fault()
    │                            │
    │                            ├─ PTE 存在但无写权限
    │                            │   └─ do_wp_page() → 写时复制
    │                            │
    │                            └─ PTE 存在但页面已 swap 出去
    │                                └─ do_swap_page() → swapin
    │
    ├─ address 不在任何 VMA 内 ──→ 用户态 → SIGSEGV
    │                             内核态 → kernel oops
    │
    └─ 内核缺页 (vmalloc 区等) → vmalloc_fault()
```

### error_code 解析

```
Bit 0: 0=缺页, 1=保护违例
Bit 1: 0=读/执行, 1=写
Bit 2: 0=内核态, 1=用户态
Bit 3: 1=保留位错误（如大页标记错误）
Bit 4: 1=指令获取（NX 违例）
```

## Demand Paging (请求分页)

Linux 不会在进程创建或 `mmap` 后立即分配物理页，而是等到实际访问时才通过缺页处理分配：

```c
// mmap 只设置 VMA，不分配物理页
void *addr = mmap(NULL, 1024 * 1024,          // 1 MB
                  PROT_READ | PROT_WRITE,
                  MAP_PRIVATE | MAP_ANONYMOUS,
                  -1, 0);
// 此时只有 VMA 记录，无物理页分配

// 第一次写入 → Minor Fault → do_anonymous_page() → 分配物理页
addr[0] = 'x';  // 触发缺页
```

**优点**:

* 按需分配，节省内存
* 创建进程时只复制页表结构，不复制物理页
* 共享库只有一份物理内存

## Copy-on-Write (写时复制)

`fork()` 创建子进程时，父子进程共享所有物理页，PTE 标记为只读：

```c
pid_t pid = fork();
// fork() 后父子进程共享物理页（PTE 全部标记为只读）

if (pid == 0) {
    // 子进程：写入触发 do_wp_page()
    shared_var = 42;  // → COW: 复制物理页，分配新页给子进程
} else {
    // 父进程：继续使用原页（PTE 更新为可写）
    wait(NULL);
}
```

### COW 处理流程

```
1. 写入只读 PTE → 触发缺页
2. error_code 显示"写操作 + 保护违例"
3. do_wp_page() 判断：
   a. 此页只被一个进程引用 → 直接赋予写权限
   b. 此页被多个进程引用（通过 struct page->_mapcount）→ 复制新页
4. 新页复制原始内容，更新 PTE 为可写
5. 原页引用计数减 1
```

## 匿名页缺页 (Anonymous Page)

第一次访问匿名映射页的处理：

```c
// do_anonymous_page() 的处理逻辑简化版：
static vm_fault_t do_anonymous_page(struct vm_fault *vmf)
{
    struct page *page;

    // 如果是读触发，映射到零页（共享）
    if (!(vmf->flags & FAULT_FLAG_WRITE)) {
        // 使用 ZERO_PAGE（所有只读零页共享同一物理页）
        page = ZERO_PAGE(vmf->address);
        // ... 建立映射，PTE 设置为只读
        return 0;
    }

    // 写触发 → 分配新物理页
    page = alloc_zeroed_user_highpage(vmf->vma, vmf->address);
    // ... 建立映射，PTE 设置为可写
    return 0;
}
```

## 文件映射缺页 (File-backed Fault)

访问 `mmap` 映射的文件区域时的处理：

```
do_fault()
    │
    ├─ 读缺页 → filemap_fault()
    │   │  检查 Page Cache → 命中 → 映射到进程地址空间（Minor）
    │   │                   → 未命中 → 从磁盘读入页（Major）
    │   └─ 预读 (readahead)：同步读入相邻页
    │
    ├─ 写缺页 → __do_fault() → filemap_fault() 读页 → mark_page_accessed()
    │        → 如果是共享映射 → 直接写（Wait-On-Disk）
    │        → 如果是私有映射 → COW（同匿名页）
    │
    └─ COW 缺页 → do_cow_fault()
```

## Swap 缺页 (Swap-in)

物理内存不足时，内核将不活跃的匿名页换出到 Swap 分区，PTE 中编码换出位置：

```
swap 出去的 PTE 格式：
┌─────────────────────────────────────────────────────────────────┐
│  Present=0 | Swap Offset | Swap Type | 保护位  | _PAGE_SWP_SOFT_DIRTY │
└─────────────────────────────────────────────────────────────────┘
```

访问已换出的页面时：

```
do_swap_page()
    │ 1. 从 PTE 提取 swap_entry_t (type + offset)
    │ 2. 查找 swap cache (避免重复换入)
    │ 3. 从 Swap 分区读回物理页 → swap_readpage()
    │ 4. 更新 PTE，取消 swap 标记
    │ 5. 如果页面在 Swap Cache 中有多个引用 → COW 保护
    └─ 计数统计 (pswpin/pswpout)
```

## 与用户态的交互

### madvise

`madvise` 允许应用程序向内核传达内存使用模式，影响缺页行为和页面置换决策：

```c
#include <sys/mman.h>

void *addr = mmap(NULL, 4 * 1024 * 1024,
                  PROT_READ | PROT_WRITE,
                  MAP_PRIVATE | MAP_ANONYMOUS,
                  -1, 0);

// 告诉内核这 4MB 会顺序访问 → 启用 readahead
madvise(addr, 4 * 1024 * 1024, MADV_SEQUENTIAL);

// 告诉内核这 4MB 是随机访问 → 不需要 readahead
madvise(addr, 4 * 1024 * 1024, MADV_RANDOM);

// 提示内核尽快释放页面（如缓存清理后）
madvise(addr, 4 * 1024 * 1024, MADV_DONTNEED);

// 提前预读页面到内存（类似 prefetch）
madvise(addr, 4 * 1024 * 1024, MADV_WILLNEED);
```

### 缺页统计

```bash
# 查看进程缺页情况
cat /proc/<pid>/stat
# 字段:
#   9 (minflt)  — Minor Fault 总数
#   11 (majflt) — Major Fault 总数

# 实时追踪缺页
perf stat -e page-faults,minor-faults,major-faults ./my_program

# 使用 time 命令
/usr/bin/time -v ./my_program
# Minor (reclaim+pagefaults):  1234
# Major (pagefaults):             5
```

### 缺页对性能的影响

| 缺页类型 | 延迟量级 | 影响 |
|----------|----------|------|
| Minor Fault | ~100 ns - 1 µs | 仅页表操作，几乎无感 |
| Major Fault (SSD) | ~50 - 200 µs | 明显的 I/O 等待 |
| Major Fault (HDD) | ~5 - 15 ms | 严重性能下降 |
| Swap In (HDD) | ~10 - 20 ms | 应避免的高延迟场景 |
