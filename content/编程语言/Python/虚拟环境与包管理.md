## Python 虚拟环境与包管理

### 为什么需要虚拟环境

Python 项目通常依赖不同的第三方包，且版本需求可能冲突：

* **项目 A** 需要 `requests==2.28.0`
* **项目 B** 需要 `requests==2.31.0`

如果不隔离环境，全局安装会发生版本冲突。**虚拟环境**为每个项目创建独立的 Python 环境，包含各自的解释器、`site-packages` 目录和可执行文件。

### venv（Python 3.3+）

Python 内置的虚拟环境工具，无需额外安装。

```bash
# 创建虚拟环境
python3 -m venv myproject_env

# 激活虚拟环境（Linux/macOS）
source myproject_env/bin/activate

# 激活虚拟环境（Windows）
# myproject_env\Scripts\activate

# 激活后，终端会显示环境名
# (myproject_env) $

# 停用虚拟环境
deactivate

# 删除虚拟环境（直接删除目录即可）
rm -rf myproject_env
```

激活虚拟环境后，`pip install` 安装的包会自动放入环境的 `site-packages` 目录，不会影响全局 Python。

### pip

Python 的官方包管理器。

```bash
# 安装包
pip install requests
pip install requests==2.28.0         # 指定版本
pip install "requests>=2.28,<3.0"   # 版本范围
pip install -U requests              # 升级到最新

# 从 requirements.txt 安装
pip install -r requirements.txt

# 卸载
pip uninstall requests

# 列出已安装包
pip list
pip list --format=freeze            # 输出为 freeze 格式

# 检查过时包
pip list --outdated

# 查看包信息
pip show requests

# 从其他源安装
pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple
```

#### requirements.txt

最传统的依赖管理方式：

```
# requirements.txt
requests==2.28.0
numpy>=1.24,<2.0
flask>=2.3
# 从 Git 仓库安装
git+https://github.com/author/repo.git@v1.0
# 本地开发模式
-e ./my-local-package
```

```bash
# 生成 requirements.txt（当前环境所有包）
pip freeze > requirements.txt

# 只安装顶层依赖（不包含传递依赖）——需要 pip-tools
pip-compile requirements.in > requirements.txt
```

### pyproject.toml（PEP 517 / 518 / 621）

现代 Python 项目的标准配置文件，替代 `setup.py` / `setup.cfg` / `requirements.txt`。

```toml
[build-system]
requires = ["setuptools>=68.0", "wheel"]
build-backend = "setuptools.build_meta"

[project]
name = "myproject"
version = "0.1.0"
description = "示例项目"
authors = [{name = "Alice", email = "alice@example.com"}]
requires-python = ">=3.10"
dependencies = [
    "requests>=2.28",
    "numpy>=1.24",
    "flask>=2.3",
]

[project.optional-dependencies]
dev = [
    "pytest>=7.0",
    "black>=23.0",
    "mypy>=1.0",
]
test = [
    "pytest>=7.0",
    "pytest-cov>=4.0",
]

# 安装方法
# pip install .                  # 安装项目
# pip install ".[dev]"          # 安装额外依赖
# pip install -e .              # 可编辑安装（开发模式）
```

### pip install -e（开发模式）

将项目以「符号链接」方式安装，源代码修改立即生效，无需重新安装：

```bash
# 在项目根目录（有 pyproject.toml 或 setup.py）
pip install -e .

# 测试修改：修改源代码后直接生效
python -c "from myproject import hello; print(hello())"
```

### conda / miniconda

适用于需要非 Python 依赖的场景（如 CUDA 库、系统库、C 扩展）。

```bash
# 创建环境
conda create -n myenv python=3.12

# 激活
conda activate myenv

# 安装包
conda install numpy pandas pytorch-cuda=12.1 -c pytorch

# 列出环境
conda env list

# 导出/导入环境
conda env export > environment.yml
conda env create -f environment.yml

# 删除环境
conda remove -n myenv --all
```

**conda vs pip：**

| 特性 | pip | conda |
|------|-----|-------|
| 语言 | 仅 Python | 任意语言（Python / C / R 等） |
| 依赖解析 | 较简单 | 更强（SAT 求解器） |
| 非 Python 依赖 | 需系统安装 | 内置支持 |
| 默认源 | PyPI | Anaconda 仓库 |
| 环境工具 | venv + pip | 内置 |

### 现代替代方案

#### pipenv

结合 Pipfile + Pipfile.lock，自动管理虚拟环境：

```bash
pip install pipenv
pipenv install requests              # 安装并自动创建 venv
pipenv install --dev pytest          # 开发依赖
pipenv shell                         # 进入虚拟环境
pipenv lock                          # 生成 Pipfile.lock
```

#### poetry

更完整的依赖管理和打包工具：

```bash
curl -sSL https://install.python-poetry.org | python3 -
poetry new myproject                 # 创建新项目
poetry add requests                  # 添加依赖
poetry add --group dev pytest        # 开发依赖
poetry shell                         # 进入虚拟环境
poetry build                         # 构建 wheel
poetry publish                        # 发布到 PyPI
```

#### uv（新兴，高性能）

Rust 编写，比 pip 快 10-100 倍：

```bash
pip install uv
uv pip install requests              # 替代 pip install
uv venv                             # 创建虚拟环境
uv pip compile requirements.in -o requirements.txt  # 锁定依赖
uv pip sync requirements.txt         # 同步环境
```

### PYTHONPATH 与 site-packages

```bash
# PYTHONPATH：解释器启动时额外添加的搜索路径
export PYTHONPATH=/my/libs:$PYTHONPATH
python -c "import sys; print(sys.path)"

# site-packages：第三方包安装目录
python -c "import site; print(site.getsitepackages())"

# 查看当前包的安装位置
pip show numpy | grep Location
```

### 从多种来源安装

```bash
# PyPI
pip install requests

# Git 仓库
pip install git+https://github.com/psf/requests.git
pip install git+https://github.com/psf/requests.git@v2.28.0
pip install git+ssh://git@github.com/psf/requests.git

# 本地 wheel 文件
pip install ./dist/myproject-0.1.0-py3-none-any.whl

# 本地 sdist（源码发布）
pip install ./dist/myproject-0.1.0.tar.gz

# 可编辑安装
pip install -e ./my-local-package
```

### 完整工作流示例

```bash
# 1. 创建项目目录
mkdir myproject && cd myproject

# 2. 创建虚拟环境
python3 -m venv .venv

# 3. 激活虚拟环境
source .venv/bin/activate

# 4. 创建 pyproject.toml
cat > pyproject.toml << 'EOF'
[build-system]
requires = ["setuptools>=68.0", "wheel"]
build-backend = "setuptools.build_meta"

[project]
name = "myproject"
version = "0.1.0"
dependencies = [
    "requests>=2.28",
]
EOF

# 5. 安装依赖
pip install -e .

# 6. 导出依赖清单
pip freeze > requirements.txt

# 7. 开发完毕后，可以可重复安装
pip install -r requirements.txt

# 8. 退出虚拟环境
deactivate
```
