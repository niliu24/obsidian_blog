> 哈希表（Hash Table）通过哈希函数将 key 映射到数组索引，实现 O(1) 期望时间的插入、删除和查找。它是现代软件中最常用的数据结构之一，几乎所有编程语言标准库都提供开箱即用的实现。核心挑战在于：设计好的哈希函数、解决冲突、以及动态扩容。

## 核心原理

```
key → [哈希函数] → hash code → [取模] → bucket index → 存储 value
```

| 组件 | 说明 |
|------|------|
| **哈希函数** | 将任意类型 key 映射为整数。要求：确定性、均匀分布、计算快速 |
| **桶数组** | 底层存储，大小为 2 的幂（方便位运算取模） |
| **负载因子** | α = n / m（元素数 / 桶数）。α 过高 → 冲突增多→性能下降 |

## 冲突解决

### 1. 链地址法 (Chaining)

每个桶是一个链表（或平衡树）。Java `HashMap`、C++ `std::unordered_map` 采用此方式。

```
bucket[0] → node → node → NULL
bucket[1] → NULL
bucket[2] → node → node → node → NULL
bucket[3] → NULL
```

当单个桶内链表过长（如 JDK 8 中 > 8 个节点）时，可退化为红黑树以保证最坏 O(log n)。

### 2. 开放寻址法 (Open Addressing)

冲突时按探测序列找下一个空桶。Python `dict`、Go `map`、Redis hash 采用此方式。

| 探测方式 | 公式 | 优势 | 劣势 |
|----------|------|------|------|
| 线性探测 | `h(k, i) = (h(k) + i) mod m` | 缓存友好 | 聚集效应 |
| 平方探测 | `h(k, i) = (h(k) + i²) mod m` | 减少聚集 | 可能无法覆盖全部桶 |
| 双重哈希 | `h(k, i) = (h₁(k) + i·h₂(k)) mod m` | 最小聚集 | 计算开销大 |

## 动态扩容

当负载因子超过阈值（如 0.75），触发 rehash：

```
1. 分配新数组 (大小 ×2)
2. 遍历旧表所有元素，重新哈希到新表
3. 释放旧表
```

扩容是 O(n) 的，但均摊到每次插入仍为 O(1)。Redis 使用**渐进式 rehash**，分多次逐步迁移，避免单次扩容阻塞服务。

## 简单实现 (链地址法)

```cpp
class MyHashMap {
    static const int CAP = 769;  // 质数桶数
    vector<list<pair<int, int>>> buckets;

    int hash(int key) { return key % CAP; }

public:
    MyHashMap() : buckets(CAP) {}

    void put(int key, int value) {
        int idx = hash(key);
        for (auto& [k, v] : buckets[idx]) {
            if (k == key) { v = value; return; }
        }
        buckets[idx].emplace_back(key, value);
    }

    int get(int key) {
        int idx = hash(key);
        for (auto& [k, v] : buckets[idx])
            if (k == key) return v;
        return -1;
    }

    void remove(int key) {
        int idx = hash(key);
        buckets[idx].remove_if(
            [key](auto& p) { return p.first == key; });
    }
};
```

## 各语言实现对比

| 特性 | C++ `unordered_map` | Java `HashMap` | Python `dict` | Go `map` |
|------|--------------------|---------------|--------------|---------|
| 冲突解决 | 链地址 | 链地址 + 红黑树 | 开放寻址 | 开放寻址 |
| 默认容量 | 16 | 16 | 8 | 随 hint 调整 |
| 扩容阈值 | load_factor > 1.0 | load_factor > 0.75 | 2/3 满 | load_factor > 0.65 |
| 迭代顺序 | 无序 | 无序 | **插入顺序** (3.7+) | 随机化 seed |
