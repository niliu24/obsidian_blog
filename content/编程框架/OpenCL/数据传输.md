OpenCL 中 Host 与 Device 之间的数据交换通过命令队列以异步方式完成。主要有三种方式：显式 `Read/Write`、`Map/Unmap` 零拷贝映射、以及 OpenCL 2.0+ 的 SVM 共享虚拟内存（SVM 见 [内存对象详解](内存对象详解.md)）。

## 显式数据传输

```c
// Host → Device（写）
cl_int clEnqueueWriteBuffer(cl_command_queue queue,
                            cl_mem buffer,
                            cl_bool blocking,         // CL_TRUE 阻塞, CL_FALSE 异步
                            size_t offset,            // device 端起始偏移
                            size_t size,              // 字节数
                            const void *ptr,          // host 端数据源
                            cl_uint num_events,
                            const cl_event *wait_list,
                            cl_event *event);

// Device → Host（读）
cl_int clEnqueueReadBuffer(cl_command_queue queue,
                           cl_mem buffer,
                           cl_bool blocking,
                           size_t offset,
                           size_t size,
                           void *ptr,
                           cl_uint num_events,
                           const cl_event *wait_list,
                           cl_event *event);
```

```c
// 阻塞写：写完后才返回
clEnqueueWriteBuffer(queue, d_a, CL_TRUE, 0, sizeof(float) * N, a, 0, NULL, NULL);

// 异步写：立即返回，通过事件跟踪
cl_event write_evt;
clEnqueueWriteBuffer(queue, d_a, CL_FALSE, 0, sizeof(float) * N, a, 0, NULL, &write_evt);
```

异步传输配合 events 可实现数据传输与 kernel 执行的流水线重叠。

### blocking 与 event 的关联

`blocking` 和 `event` 是两个独立参数，组合后产生四种语义：

| blocking | event | 行为 |
|----------|-------|------|
| `CL_TRUE` | `NULL` | 同步阻塞，函数返回时传输已完成，无事件可查询 |
| `CL_TRUE` | `非NULL` | 同步阻塞，函数返回时传输已完成，**event 仍被创建**，可获取 profiling 信息 |
| `CL_FALSE` | `NULL` | 异步发射即返回，无法跟踪状态（fire-and-forget） |
| `CL_FALSE` | `非NULL` | 异步发射即返回，通过 event 查询状态、等待、链式同步 |

关键点：

* `blocking=CL_TRUE` 本质上等价于 `CL_FALSE` + 内部 `clWaitForEvents`，但 event 对象在阻塞模式下**依然有效**——可以获取 `CL_PROFILING_COMMAND_START/END` 时间戳
* `blocking=CL_FALSE` + `event=NULL` 是危险的：无法知道传输何时完成，后续 kernel 可能在数据就绪前执行
* 即使设置了 `blocking=CL_TRUE`，仍应检查返回值和 `errcode_ret`——阻塞只保证等待，不保证成功

```c
// 阻塞 + 无 event：最简单，适合调试和简单场景
clEnqueueWriteBuffer(queue, d_a, CL_TRUE, 0, size, a, 0, NULL, NULL);

// 阻塞 + 有 event：阻塞等待，但后续可查 profiling 数据
cl_event evt;
clEnqueueWriteBuffer(queue, d_a, CL_TRUE, 0, size, a, 0, NULL, &evt);
cl_ulong start, end;
clGetEventProfilingInfo(evt, CL_PROFILING_COMMAND_START, sizeof(start), &start, NULL);
clGetEventProfilingInfo(evt, CL_PROFILING_COMMAND_END, sizeof(end), &end, NULL);
printf("传输耗时: %.3f ms\n", (end - start) * 1e-6);

// 异步 + 有 event：流水线关键——传输与计算重叠
cl_event write_evt, kernel_evt;
clEnqueueWriteBuffer(queue, d_a, CL_FALSE, 0, size, a, 0, NULL, &write_evt);
clEnqueueNDRangeKernel(queue, kernel, 1, NULL, &global, &local,
                       1, &write_evt, &kernel_evt);  // kernel 等待 write_evt 完成
// Host 端可继续提交其他 queue 的命令或做 CPU 端准备工作
clWaitForEvents(1, &kernel_evt);
```

`clFinish` 与 `blocking` 的关系：`blocking=CL_TRUE` 仅等待**该命令**完成，`clFinish` 等待**整个队列**的所有命令完成。若队列中有多个异步命令，用 `clFinish` 确保全部完成。

## Map / Unmap（零拷贝传输）

将 device buffer 映射到 host 地址空间，直接读写映射区域，避免显式 Copy：

```c
void *clEnqueueMapBuffer(cl_command_queue queue,
                         cl_mem buffer,
                         cl_bool blocking,
                         cl_map_flags map_flags,    // CL_MAP_READ / CL_MAP_WRITE / CL_MAP_WRITE_INVALIDATE_REGION
                         size_t offset,
                         size_t size,
                         cl_uint num_events,
                         const cl_event *wait_list,
                         cl_event *event,
                         cl_int *errcode_ret);

cl_int clEnqueueUnmapMemObject(cl_command_queue queue,
                               cl_mem memobj,
                               void *mapped_ptr,
                               cl_uint num_events,
                               const cl_event *wait_list,
                               cl_event *event);
```

```c
// Map 到 host 可写
float *mapped = (float *)clEnqueueMapBuffer(
    queue, d_c, CL_TRUE, CL_MAP_READ, 0, sizeof(float) * N, 0, NULL, NULL, &err);
// 直接读写 mapped[0..N-1]...
clEnqueueUnmapMemObject(queue, d_c, mapped, 0, NULL, NULL);
```

| Map Flag | 说明 |
|---------|------|
| `CL_MAP_READ` | Host 将读取映射区域 |
| `CL_MAP_WRITE` | Host 将写入映射区域 |
| `CL_MAP_WRITE_INVALIDATE_REGION` | Host 将覆写整个区域（device 原值可能丢弃，性能更好） |

Map 的内存分配时加 `CL_MEM_ALLOC_HOST_PTR` 可实现真正的零拷贝。Map/Unmap 必须配对调用。

## 传输策略选型

| 场景 | 推荐方式 |
|------|---------|
| 数据只传一次 | `clCreateBuffer` + `CL_MEM_COPY_HOST_PTR` |
| 频繁读写 | Map/Unmap + `CL_MEM_ALLOC_HOST_PTR` |
| Host 和 Device 共享内存 | `CL_MEM_USE_HOST_PTR`（注意一致性） |
| 数据仅设备内部使用 | 不带 host 相关 flag |
| 流水线优化 | 异步传输 + events 重叠 |
