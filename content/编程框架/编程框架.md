> 编程框架为开发者提供高层抽象和标准化的编程模型，屏蔽底层硬件细节，以提升开发效率和代码可移植性。在 GPU 计算领域中，CUDA、HIP、OpenCL 构成了从专有到开放的光谱。

## 框架对比

| 特性 | CUDA | HIP | OpenCL |
|------|------|-----|--------|
| 维护方 | NVIDIA | AMD | Khronos Group |
| 开放性 | 专有 | 开源 | 开放标准 |
| 支持硬件 | NVIDIA GPU | AMD GPU + NVIDIA GPU | GPU/CPU/FPGA/DSP |
| Kernel 语言 | CUDA C++ | HIP C++ | OpenCL C (C99) |
| 编译器 | nvcc | hipcc | 各厂商自有 |
| 线程层次 | Grid→Block→Warp→Thread | 同 CUDA | NDRange→Work-Group→Work-Item |
| 性能 | 最优（NVIDIA 原生） | 接近 CUDA | 取决于实现 |
| 生态成熟度 | 最高 | 快速成长 | 广泛但碎片化 |
| 适用场景 | NVIDIA 独占开发 | 跨平台 GPU 移植 | 异构跨厂商兼容 |

### 选型建议

- **NVIDIA GPU 独占** → CUDA：性能最优，生态最成熟
- **AMD + NVIDIA 跨平台** → HIP：类 CUDA 语法，代码移植成本低
- **多厂商/多设备类型** → OpenCL：唯一支持 FPGA/DSP 的选择
