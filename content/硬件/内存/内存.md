> 内存是计算机系统的核心部件，处于 CPU 与存储设备之间的数据通道。从 CPU 寄存器到远程存储，不同层次存储介质的访问速度横跨 **6 个数量级**，理解存储层次结构是软件性能优化的基础。

## 存储层次金字塔

现代计算机系统使用分层存储架构来平衡**速度**与**容量**之间的矛盾。越靠近 CPU 的存储层次，速度越快、容量越小、成本越高。

```
CPU Registers              ~0.3 ns
    │
L1 Cache (SRAM, 32-64KB)   ~1 ns
    │
L2 Cache (SRAM, 256KB-1MB) ~5 ns
    │
L3 Cache (SRAM, 8-64MB)    ~10 ns
    │
DRAM 主存 (DDR4/5)          ~100 ns
    │
NVMe SSD (Flash)            ~10 μs
    │
HDD (机械磁盘)               ~10 ms
```

### 延迟对比表

| 层次 | 介质 | 典型延迟 | 相对 DRAM 倍数 | 典型容量 |
|------|------|---------|---------------|---------|
| L1 Cache | SRAM | ~1 ns | 100x 更快 | 32-64 KB |
| L2 Cache | SRAM | ~5 ns | 20x 更快 | 256 KB-1 MB |
| L3 Cache | SRAM | ~10 ns | 10x 更快 | 8-64 MB |
| DRAM | DRAM | ~100 ns | 1x | 8-512 GB |
| NVMe SSD | NAND Flash | ~10 μs | 100x 更慢 | 256 GB-8 TB |
| HDD | 磁盘 | ~10 ms | 100,000x 更慢 | 1-20 TB |
| 网络存储 | 远端 | ~1-10 ms | 10,000-100,000x 更慢 | 不限 |

## 为什么要关注内存层次

### 缓存命中率对性能的影响

以现代 CPU (例如 4 GHz) 为例，一条 CPU 指令约 0.25 ns，一次 L1 缓存命中为 **4 个周期**，而一次 DRAM 访问需要 **400 个周期**：

```
L1 Hit (4 cycles)     →  1 ns
L2 Hit (15 cycles)    →  4 ns
L3 Hit (40 cycles)    → 10 ns
DRAM (200-400 cycles) → 50-100 ns
```

这意味着 DRAM 访问的延迟约是 L1 缓存的 **100 倍**。写得不好的内存访问模式（如随机访问大型数组）会导致 CPU 频繁 Stall，性能下降数十倍。

```c
// 缓存友好：连续访问
for (int i = 0; i < N; i++)
    sum += a[i];  // 按序访问 → 硬件预取友好 → 缓存命中率高

// 缓存不友好：跳步访问
for (int i = 0; i < N; i++)
    sum += a[stride * i];  // 跳跃访问 → 缓存行浪费 → 大量缓存未命中
```

### 内存墙 (Memory Wall)

**内存墙**指的是 CPU 运算速度的增长远超内存访问速度的增长，导致**内存访问延迟成为系统性能瓶颈**这一持续扩大的差距：

```
CPU 性能增长: ~50%/年（摩尔定律时代）
DRAM 延迟改善: ~7%/年
差距: 每年扩大 ~40%
```

内存墙对软件设计的启示：

* **数据局部性**优先：时间局部性（重复访问同一数据）+ 空间局部性（访问邻近数据）
* **缓存感知算法**：如 Cache Oblivious 算法、分块矩阵乘法（Tiling）
* **减少随机访问**：B+ 树、LSM-Tree 等数据结构的设计初衷
* **异步/预取**：CPU 在执行当前数据的同时预取下一个需要的数据
* **计算压入内存**：Near-Memory Computing (如 CXL 主控计算)、Processing-In-Memory (PIM)

## NUMA 与非一致内存访问

在多路 CPU 系统中，每个 CPU 的本地 DRAM 访问延迟远低于访问远端 CPU 的内存——这是 **NUMA (Non-Uniform Memory Access)** 架构。详见 [NUMA](../../../Raw/NUMA.md)。
