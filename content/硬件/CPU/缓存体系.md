> CPU 缓存（Cache）是位于 CPU 和主存之间的**高速小容量存储器**，通过利用**局部性原理**弥合 CPU 与 DRAM 之间数量级的速度差距。理解缓存行为是编写高性能代码的基础。

## 内存层次金字塔

```
              存储层次                          典型延迟
          ┌──────────────┐
          │   寄存器      │      ◄──── 0.3 ns (1 周期)
          │  ~500 字节    │
          ├──────────────┤
          │  L1 缓存      │      ◄──── 1 ns (3-5 周期)
          │  32-64 KB     │
          ├──────────────┤
          │  L2 缓存      │      ◄──── 4 ns (10-15 周期)
          │  256-512 KB   │
          ├──────────────┤
          │  L3 缓存      │      ◄──── 10 ns (30-50 周期)
          │  2-32 MB      │
          ├──────────────┤
          │  DRAM 主存    │      ◄──── 100 ns (200-300 周期)
          │  8-512 GB     │
          ├──────────────┤
          │  SSD (NVMe)   │      ◄──── 10 μs
          │  256 GB-2 TB  │
          ├──────────────┤
          │  HDD          │      ◄──── 10 ms
          │  1-20 TB      │
          └──────────────┘
```

| 层级 | 典型容量 | 延迟 | 带宽 | 管理 |
|------|---------|------|------|------|
| L1 缓存 | 32-64 KB (指令 + 数据分离) | ~1 ns | ~1 TB/s | 硬件 |
| L2 缓存 | 256-512 KB (每核私有) | ~4 ns | ~500 GB/s | 硬件 |
| L3 缓存 | 2-32 MB (多核共享, LLC) | ~10 ns | ~200 GB/s | 硬件 |
| DRAM | 8-512 GB | ~100 ns | ~50 GB/s | 操作系统 |

> **LLC** (Last-Level Cache) 即最后一级缓存，通常指 L3。

## 缓存组织方式

### 直接映射 (Direct-Mapped)

每个内存地址映射到缓存中**唯一**的位置。

```
内存地址 → 索引 (Index) → 定位缓存行
          → 标签 (Tag) → 比较确认命中
          → 偏移 (Offset) → 定位行内字节

地址划分: [ Tag | Index | Offset ]
```

### 组相联 (Set-Associative)

每个索引位置对应一组（Set），组内有多路（Way），查找时遍历组内所有路。

| 相联度 | 说明 | 优缺点 |
|--------|------|--------|
| 直接映射 (1-way) | 一路为一组 | 简单、快速、冲突率高 |
| 2-way | 两组候选 | 冲突率降低 |
| 4-way | 四组候选 | 常见于 L1 |
| 8-way | 八组候选 | 常见于 L2 |
| 16-way | 十六组候选 | 常见于 L3/LLC |
| 全相联 (N-way) | 所有位置 | 冲突率最低、硬件复杂（仅用于 TLB） |

### 全相联 (Fully Associative)

缓存行可存放在任何位置，查找时需要遍历所有缓存行。硬件成本高，仅用于小的结构（如 TLB）。

```
直接映射:        组相联 (4-way):          全相联:
┌────┐           ┌────┬────┬────┬────┐    ┌────┬────┬────┬────┐
│ 1  │           │1a  │1b  │1c  │1d  │    │ a  │ b  │ c  │ d  │
├────┤           ├────┼────┼────┼────┤    ├────┼────┼────┼────┤
│ 2  │           │2a  │2b  │2c  │2d  │    │ e  │ f  │ g  │ h  │
├────┤           ├────┼────┼────┼────┤    ├────┼────┼────┼────┤
│ 3  │           │3a  │3b  │3c  │3d  │    │ i  │ j  │ k  │ l  │
├────┤           ├────┼────┼────┼────┤    ├────┼────┼────┼────┤
│ 4  │           │4a  │4b  │4c  │4d  │    │ m  │ n  │ o  │ p  │
└────┘           └────┴────┴────┴────┘    └────┴────┴────┴────┘
```

## 缓存行 (Cache Line)

缓存与内存之间的基本传输单元，现代 CPU 上**固定为 64 字节**。

| 架构 | 缓存行大小 |
|------|-----------|
| x86 (Intel/AMD) | 64 字节 |
| ARM (AArch64) | 64 字节 |
| RISC-V (通用) | 64 字节 |

缓存行为 64 字节意味着：访问 `arr[0]` 后，`arr[0..15]`（int 数组的 16 个元素）都会被自动加载到缓存中（空间局部性）。

## 缓存一致性协议

### MESI 协议

多核共享内存场景下，每个缓存行维护 4 种状态：

```
                      ┌──────────────────┐
                      │    Modified (M)   │◄── 1. 仅本核拥有
                      │   脏数据，未写回内存 │   2. 已被修改
                      └────────┬─────────┘   3. 需写回内存再共享
                               │
                               │ 写丢失 (BusRdX)
                               ▼
                      ┌──────────────────┐
              ┌──────►│   Exclusive (E)   │◄── 1. 仅本核拥有
              │       │   干净数据，与内存一致 │   2. 未被修改
              │       └────────┬─────────┘
              │                │
              │                │ 读丢失，其他核取数据
              │                ▼
              │       ┌──────────────────┐
              │       │   Shared (S)      │◄── 1. 多核拥有
              │       │   干净数据，与内存一致 │   2. 可以丢弃（不用写回）
              │       └────────┬─────────┘
              │                │
              │                │ 写命中
              │                ▼
              │       ┌──────────────────┐
              └───────│   Invalid (I)     │◄── 1. 缓存行无效
                      └──────────────────┘   2. 需重新加载
```

| 状态 | 本核有效？ | 内存同步？ | 其他核心副本？ | 写操作是否需要总线事务 |
|------|-----------|-----------|--------------|---------------------|
| M (Modified) | 是 | 否（脏） | 无 | 否（直接写） |
| E (Exclusive) | 是 | 是 | 无 | 否（直接写，产生窥探） |
| S (Shared) | 是 | 是 | 可能有 | 需总线广播失效 |
| I (Invalid) | 否 | — | 可能有或没有 | 需总线事务加载 |

> 从 M 到 S 的转换需要将脏数据写回内存（写回 + 总线共享信号）。
>
> 现代 Intel CPU 使用 **MESIF** 协议（增加 F 状态，指定一个核作为转发者），AMD 使用 **MOESI** 协议（增加 O 状态，允许一个核持有脏数据的同时其他核持有干净副本）。

## 局部性原理

| 类型 | 定义 | 示例 |
|------|------|------|
| **时间局部性** | 最近访问的数据很可能再次被访问 | 循环变量、累加器 |
| **空间局部性** | 访问某地址后，附近地址也很可能被访问 | 数组顺序遍历 |

```c
// 好的空间局部性：顺序访问
int sum_array_rows(int matrix[N][N]) {
    int sum = 0;
    for (int i = 0; i < N; i++)        // 外层行
        for (int j = 0; j < N; j++)    // 内层列
            sum += matrix[i][j];       // 地址连续，缓存友好
    return sum;
}

// 差的空间局部性：跳跃访问
int sum_array_cols(int matrix[N][N]) {
    int sum = 0;
    for (int j = 0; j < N; j++)        // 外层列
        for (int i = 0; i < N; i++)    // 内层行
            sum += matrix[i][j];       // 按列遍历，跨行跳跃，缓存不友好
    return sum;
}
```

## 伪共享 (False Sharing)

不同核心修改**同一缓存行**中不同变量时，MESI 协议强制在核心之间反复传递整个缓存行，导致严重的性能退化。

```c
// ❌ 伪共享示例
struct Counter {
    int a;         // 核心 0 频繁修改
    char pad[60];  // 补齐到 64 字节（可选）
    int b;         // 核心 1 频繁修改
};                 // a 和 b 在同一缓存行！

// 两个线程分别修改 a 和 b：
// 核心 0 改 a → 缓存行变成 M，核心 1 的缓存行变成 I
// 核心 1 改 b → 需要从核心 0 获取缓存行
// 结果：每次修改都在核心间传递 64 字节的缓存行，而非 4 字节的 int
```

```c
// ✅ 修复伪共享：缓存行对齐（填充）
struct Counter {
    int a;
    char padding[60];  // 填充到 64 字节，使 a 独占一个缓存行
};

struct Counter2 {
    int b;
    char padding[60];
};
// a 和 b 在不同的缓存行上，各自独立
```

> 在 C11/C++11 中可以使用 `alignas(64)` 让变量按缓存行对齐。C++17 提供了 `std::hardware_destructive_interference_size` 辅助检测伪共享边界。

## 缓存友好优化技巧

### 1. 结构体布局 (SoA vs AoS)

```c
// AoS (Array of Structures) — 不友好
struct Particle {
    float x, y, z;   // 位置
    float vx, vy, vz; // 速度
    float mass;       // 质量
    int type;         // 类型
};
struct Particle particles[N];

// 遍历位置时，只用到 12 字节，但加载了整个 44 字节的结构体
for (int i = 0; i < N; i++) {
    process_position(particles[i].x, particles[i].y, particles[i].z);
    // 浪费: vx, vy, vz, mass, type 也被加载到缓存
}
```

```c
// SoA (Structure of Arrays) — 缓存友好
struct Particles {
    float *x, *y, *z;      // 位置数组（连续）
    float *vx, *vy, *vz;   // 速度数组
    float *mass;            // 质量数组
    int   *type;            // 类型数组
};

// 遍历位置时，只加载需要的数组
for (int i = 0; i < N; i++) {
    process_position(particles.x[i], particles.y[i], particles.z[i]);
    // x, y, z 各自连续存储，缓存利用率 100%
}
```

| 布局 | 缓存效率 | 适用场景 |
|------|---------|---------|
| **AoS** | 差（一次仅使用结构体部分字段） | 少量对象、频繁访问所有字段 |
| **SoA** | 好（同类数据连续排列） | 大量数据、SIMD 向量化、单字段遍历 |

### 2. 循环交换 (Loop Interchange)

```c
// 不友好：外层行、内层列 → 按列访问 → 缓存行利用率低
for (int j = 0; j < N; j++)        // 外层列
    for (int i = 0; i < N; i++)    // 内层行
        matrix[i][j] = 0;

// 友好：外层列、内层行 → 按行访问 → 顺序利用缓存行
for (int i = 0; i < N; i++)        // 外层行
    for (int j = 0; j < N; j++)    // 内层列
        matrix[i][j] = 0;
```

### 3. 分块 (Blocking / Tiling)

矩阵乘法优化经典案例：将大矩阵切分为小块，使子块能放入缓存。

```
朴素矩阵乘法 C = A × B 的访存模式：

A: [row i]  → 按行顺序读取 (缓存友好)
B: [col j]  → 按列跳跃读取 (缓存不友好)
C: [i][j]   → 写入

分块后，B 的子块可重复使用：

┌─────┐     ┌─────┐     ┌─────┐
│ A₁₁ │  ×  │ B₁₁ │  =  │ C₁₁ │
│ A₁₂ │     │ B₂₁ │     │     │
└─────┘     └─────┘     └─────┘

A₁₁ 和 B₁₁ 同时在缓存中 → 计算 C₁₁ 的一部分
A₁₁ 在缓存中重复使用 → 计算 C₁₂ 等
```

```c
// 分块矩阵乘法（Cache Blocking）
#define BLOCK 64   // 假设 L1 缓存 32 KB，BLOCK 需满足: 3 * BLOCK * BLOCK * 8 < 32KB

void matmul_blocked(float *A, float *B, float *C, int N) {
    for (int i = 0; i < N; i += BLOCK) {
        for (int j = 0; j < N; j += BLOCK) {
            for (int k = 0; k < N; k += BLOCK) {
                // 计算子块 C[i:i+B][j:j+B] += A[i:i+B][k:k+B] × B[k:k+B][j:j+B]
                for (int ii = i; ii < i + BLOCK && ii < N; ii++) {
                    for (int kk = k; kk < k + BLOCK && kk < N; kk++) {
                        for (int jj = j; jj < j + BLOCK && jj < N; jj++) {
                            C[ii * N + jj] += A[ii * N + kk] * B[kk * N + jj];
                        }
                    }
                }
            }
        }
    }
}
// 分块后，A 的子块装入缓存一次，被 B 的多列重复使用
// 相对于朴素算法，缓存缺失率可降低 10 倍以上
```

## 缓存缺失类型 (Cache Miss Types)

| 类型 | 英文 | 原因 | 缓解方法 |
|------|------|------|---------|
| **强制缺失** | Compulsory Miss | 第一次访问某数据，缓存中必然没有 | 预取 (Prefetching)、增大缓存行 |
| **容量缺失** | Capacity Miss | 工作集超过缓存容量 | 增大缓存、分块 (Tiling) |
| **冲突缺失** | Conflict Miss | 多个地址映射到同一缓存行 | 提高相联度、地址随机化 |
| **一致性缺失** | Coherence Miss | 多核 MESI 协议导致缓存行失效 | 减少共享数据写、避免伪共享 |

> 预取指令（如 x86 的 `PREFETCHT0` / `PREFETCHT1`）可以减少强制缺失。编译器会自动插入预取指令（在 `-O2` / `-O3` 下）。
