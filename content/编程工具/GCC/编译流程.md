> GCC 将源代码转换为可执行文件经过 **预处理 → 编译 → 汇编 → 链接** 四个阶段。每个阶段对应一个独立工具，GCC 作为 Driver 自动串联整个流水线。理解各阶段有助于定位编译错误、优化代码体积和性能。

## 四阶段总览

```
hello.c ──[cpp]──→ hello.i ──[cc1]──→ hello.s ──[as]──→ hello.o ──[ld]──→ hello
         预处理        编译(到汇编)       汇编(到机器码)      链接(到可执行)
```

| 阶段 | 工具 | 输入 | 输出 | GCC 选项 | 说明 |
|------|------|------|------|----------|------|
| 预处理 | `cpp` | `.c` / `.cpp` | `.i` / `.ii` | `-E` | 宏展开、`#include` 嵌入、条件编译 |
| 编译 | `cc1` / `cc1plus` | `.i` / `.ii` | `.s` | `-S` | C/C++ → 汇编代码 |
| 汇编 | `as` | `.s` | `.o` (ELF) | `-c` | 汇编 → 机器码，生成目标文件 |
| 链接 | `ld` / `collect2` | `.o` + `.a` + `.so` | ELF 可执行 / `.so` | (无 `-c`/`-S`) | 符号解析、重定位、地址绑定 |

> **注意**: `gcc -v` 会打印实际调用的每个子进程，可观察完整的驱动流程。

## 阶段一：预处理

预处理器 `cpp` 处理所有以 `#` 开头的指令：

```c
// hello.c
#include <stdio.h>           // 头文件展开
#define MSG "Hello World"    // 宏定义
#define DEBUG                 // 条件编译标记

int main() {
#ifdef DEBUG
    printf("%s\n", MSG);     // MSG 展开为 "Hello World"
#else
    printf("Release mode\n");
#endif
    return 0;
}
```

### 常用预处理选项

| 选项 | 说明 |
|------|------|
| `-DNAME` | 定义宏 `NAME` 为 1 |
| `-DNAME=VALUE` | 定义宏 `NAME` 为 `VALUE` |
| `-UNAME` | 取消宏定义 |
| `-Ipath` | 添加头文件搜索路径 |
| `-C` | 保留注释（默认删除） |
| `-P` | 抑制行标记输出 |
| `-include file` | 等效于在源文件首行 `#include "file"` |

### 实践

```bash
# 查看预处理结果
gcc -E hello.c -o hello.i
# 仅检查宏展开，不产生文件
gcc -E -dM hello.c | head -20
```

`hello.i` 是文本文件，`#include <stdio.h>` 被替换为数百行标准库声明。

## 阶段二：编译

编译阶段将预处理后的源文件变为**汇编代码**。真正工作的编译器是 `cc1`（C 语言）或 `cc1plus`（C++）：

```bash
# 从 .c 到 .s
gcc -S hello.c              # 生成 hello.s
gcc -S hello.i -o hello.s   # 从预处理文件开始
```

### 编译优化级别

| 级别 | 说明 | 编译时间 | 代码质量 |
|------|------|----------|----------|
| `-O0` | 不优化，调试友好，变量不优化掉 | 快 | 差 |
| `-O1` | 基础优化（分支、常量折叠、跳转优化） | 较快 | 中等 |
| `-O2` | 推荐级别，启用大多数常用优化（指令调度、循环优化、内联） | 中等 | 好 |
| `-O3` | 激进优化（包括函数内联、循环展开、向量化） | 慢 | 可能最好 |
| `-Os` | 以代码体积为目标优化（`-O2` 基础上禁用体积膨胀的优化） | 中等 | 好（体积小） |
| `-Ofast` | `-O3` + 忽略严格标准合规的激进优化 | 慢 | 最快但可能不标准 |

### 各优化级启用的代表性标志

| 优化项 | `-O1` | `-O2` | `-O3` | `-Os` |
|--------|-------|-------|-------|-------|
| `-fauto-inc-dec` | | | | |
| `-fbranch-count-reg` | | | | |
| `-fcombine-stack-adjustments` | | | | |
| `-fcompare-elim` | | | | |
| `-fif-conversion` | | | | |
| `-finline-functions` | | | | |
| `-funroll-loops` | | | | |
| `-ftree-vectorize` | | | | |

### -O3 特殊优化

```bash
gcc -O3 -funroll-loops -finline-functions matrix.c -o matrix
```

* `-funroll-loops`: 将循环体重复多次，减少分支开销
* `-finline-functions`: 将小函数内联到调用点，减少调用开销
* `-ftree-vectorize`: 自动向量化，生成 SIMD 指令

> **注意**: `-O3` 可能因代码膨胀导致指令缓存（I-Cache）压力增大，实际性能不一定优于 `-O2`。

## 阶段三：汇编

汇编器 `as`（GNU Assembler）将汇编代码转为机器码，生成 **ELF 目标文件**：

```bash
# 从 .s 到 .o
gcc -c hello.s -o hello.o
# 或一步到位
gcc -c hello.c            # 直接生成 hello.o
```

### ELF 目标文件结构

```
ELF Header
  ├── .text        → 可执行机器码
  ├── .data        → 已初始化的全局/静态变量
  ├── .bss         → 未初始化的全局/静态变量（不占文件空间）
  ├── .rodata      → 只读数据（字符串常量、const 变量）
  ├── .symtab      → 符号表（函数、全局变量名及其地址）
  ├── .rela.text   → 重定位表（编译器尚不知符号最终地址的记录）
  ├── .debug_*     → 调试信息（仅在 -g 编译时存在）
  └── .comment     → 编译器版本信息
```

### ELF 文件的符号视图

```
Symbol table '.symtab' contains 7 entries:
   Num:    Value  Size Type    Bind   Vis      Ndx Name
     9: 00000000    24 FUNC    GLOBAL DEFAULT    1 main
    10: 00000018    51 FUNC    GLOBAL DEFAULT    1 add
```

* `Value`: 符号在该段内的偏移（链接前是相对地址）
* `Ndx`: 所在段索引（1=.text, 2=.data, 3=.bss）
* `Bind`: `GLOBAL` 可见于外部目标文件，`LOCAL` 仅本文件

### 用 Binutils 工具查看目标文件

```bash
# 查看所有段头
objdump -h hello.o

# 反汇编 .text 段
objdump -d hello.o

# 查看符号表
nm hello.o

# 查看完整 ELF 信息
readelf -a hello.o | head -40

# 查看重定位条目
readelf -r hello.o
```

## 阶段四：链接

链接器 `ld`（通过 GCC Driver `collect2` 调用）将多个目标文件和库合并为最终可执行文件：

```bash
# 完成链接
gcc hello.o -o hello
# 链接多个 .o
gcc main.o foo.o bar.o -o app
```

### 静态链接 vs 动态链接

| 特性 | 静态链接 | 动态链接 |
|------|----------|----------|
| 库集成方式 | 将库代码**复制**进可执行文件 | 可执行文件仅记录库名，运行时加载 |
| 可执行文件体积 | 大 | 小 |
| 启动速度 | 快（无动态加载开销） | 稍慢（需 ld.so 加载和重定位） |
| 内存共享 | 每个进程独享库代码 | `libc.so` 等可在进程间共享物理内存 |
| 库更新 | 需重新链接 | 替换 `.so` 即可（兼容 soname） |
| 文件后缀 | `.a` | `.so` |
| 链接方式 | `gcc -static main.c -o main` | `gcc main.c -o main`（默认） |

### 动态链接加载过程

```
执行 hello
  → 内核加载 ELF 到内存
  → 解析 .interp 段找到 ld-linux.so（动态链接器）
  → ld-linux.so 加载依赖的 .so
  → 完成符号重定位
  → 执行 main()
```

### 查看链接依赖

```bash
# 查看可执行文件依赖的动态库
ldd hello

# 查看库的 soname 和依赖链
objdump -p libfoo.so | grep SONAME
readelf -d libfoo.so | grep NEEDED
```

## 完整编译实战

```c
// hello.c
#include <stdio.h>

#define GREETING "Hello, GCC Pipeline!"

int add(int a, int b) {
    return a + b;
}

int main() {
    int x = 40, y = 2;
    printf("%s\n", GREETING);
    printf("%d + %d = %d\n", x, y, add(x, y));
    return 0;
}
```

### 分步执行

```bash
# 1. 预处理
gcc -E hello.c -o hello.i

# 2. 编译到汇编
gcc -S hello.i -o hello.s

# 3. 汇编到目标文件
gcc -c hello.s -o hello.o

# 4. 链接到可执行
gcc hello.o -o hello

# 验证
./hello

# 检查目标文件
nm hello.o
objdump -d hello.o
```

### 编译时探测

```bash
# 查看实际调用的编译器子命令
gcc -v hello.c -o hello

# 仅编译和汇编，查看输出
gcc -save-temps hello.c   # 保留 .i .s .o 中间文件
ls hello*
```

## PIC（位置无关代码）

共享库必须编译为 PIC（Position Independent Code）：

```bash
gcc -c -fPIC foo.c -o foo.o
gcc -shared foo.o -o libfoo.so
```

PIC 使用 GOT（全局偏移表）和 PLT（过程链接表）实现地址无关访问：

```
PIC 访问全局变量:
  → 通过 PC-relative 寻址到 GOT 表项
  → GOT 表项存有全局变量的实际地址
  → 间接访问（一次额外指针解引用）
```

非 PIC 代码使用绝对地址，加载时必须重定位所有地址引用。PIC 的代价是额外的间接访存开销和寄存器占用。
