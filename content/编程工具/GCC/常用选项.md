> GCC 提供了数百个编译选项，按功能可分为输出控制、优化、调试、警告、预处理、链接、语言标准和架构相关等类别。掌握常用选项是高效使用 GCC 的基础。

## 输出控制

| 选项 | 说明 |
|------|------|
| `-o file` | 指定输出文件名 |
| `-c` | 仅编译和汇编，生成 `.o` 目标文件，不链接 |
| `-S` | 仅编译，生成汇编代码 `.s` 文件 |
| `-E` | 仅预处理，输出展开后的源码 |
| `-v` | 显示编译过程的详细命令序列 |
| `--help` | 列出所有选项 |
| `--version` | 显示 GCC 版本信息 |
| `-save-temps` | 保留 `.i`、`.s`、`.o` 中间文件 |

```bash
gcc -E hello.c -o hello.i      # 仅预处理
gcc -S hello.c -o hello.s      # 编译到汇编
gcc -c hello.c -o hello.o      # 汇编到目标文件
gcc hello.o -o hello           # 链接
gcc -save-temps hello.c -o hello  # 保留所有中间文件
```

## 优化选项

### 优化级别

| 级别 | 说明 | 典型场景 |
|------|------|----------|
| `-O0` | 不优化（默认）。变量不消除，目标代码直接对应源码 | 开发、调试 |
| `-O1` | 基础优化。分支优化、常量折叠、跳转优化 | 快速构建且需要一定优化 |
| `-O2` | **推荐级别**。启用大多数常用优化，不含以空间换时间的激进项 | 发布构建 |
| `-O3` | 激进优化。含函数内联、循环展开、自动向量化 | 计算密集场景 |
| `-Os` | 以代码体积为优先（基于 `-O2` 禁用体积膨胀项） | 嵌入式、固件 |
| `-Ofast` | `-O3` + 忽略严格标准合规（如快速数学） | 科学计算（需确认精度可接受） |

### 各优化级别启用的关键标志

```
-O1: -fbranch-count-reg -fcombine-stack-adjustments -fif-conversion ...
-O2: -O1 + -fauto-inc-dec -fschedule-insns -freorder-blocks ...
-O3: -O2 + -finline-functions -funswitch-loops -ftree-vectorize ...
-Os: -O2 + -fomit-frame-pointer ...（禁用所有体积膨胀优化）
```

### 独立优化标志

| 选项 | 说明 |
|------|------|
| `-finline-functions` | 将所有合适的函数内联展开（`-O3` 包含） |
| `-funroll-loops` | 展开循环体，减少分支和循环控制开销 |
| `-fomit-frame-pointer` | 省略帧指针（EBP/RBP），多出一个通用寄存器 |
| `-ftree-vectorize` | 自动生成 SIMD 向量化指令 |
| `-ffast-math` | 违反 IEEE/ISO 数学规则做更激进的浮点优化 |
| `-flto` | 链接时优化（Link Time Optimization），跨编译单元分析 |
| `-fprofile-generate` / `-fprofile-use` | 基于 **PGO**（Profile-Guided Optimization）的两阶段优化 |

```bash
# 链接时优化：在多文件间做内联和常量传播
gcc -O2 -flto -c foo.c
gcc -O2 -flto -c bar.c
gcc -O2 -flto foo.o bar.o -o app

# PGO 优化（两阶段）
gcc -O2 -fprofile-generate app.c -o app.prof   # 第一阶段：生成 profiling 版本
./app.prof                                       # 运行，收集 profile 数据
gcc -O2 -fprofile-use app.c -o app              # 第二阶段：利用 profile 优化
```

## 架构相关选项

| 选项 | 说明 |
|------|------|
| `-march=native` | 自动检测当前 CPU 并启用所有支持指令集 |
| `-march=haswell` | 为特定 CPU 微架构生成指令 |
| `-mtune=haswell` | 优化调度/流水线以适配特定 CPU，但兼容旧指令集 |
| `-m32` / `-m64` | 生成 32-bit / 64-bit 代码 |
| `-msse` / `-msse2` / `-msse4.2` / `-mavx` / `-mavx2` / `-mavx512f` | 启用特定 SIMD 指令集 |
| `-mno-sse` | 禁用 SSE 指令 |

### -march vs -mtune

| 选项 | 生效内容 |
|------|----------|
| `-march=X` | 允许使用 X 架构的所有指令（生成的二进制可能不在旧 CPU 上运行） |
| `-mtune=X` | 仅调度/对齐优化按 X 架构调整，指令集保持兼容 |

```bash
# 查看当前 CPU 支持的所有 march 特性
gcc -march=native -Q --help=target | grep enabled

# 为 Haswell 编译
gcc -O3 -march=haswell -o app app.c

# 为老旧 CPU 编译但按现代 CPU 调度
gcc -O2 -march=nehalem -mtune=skylake -o app app.c
```

## 调试选项

### 调试信息级别

| 选项 | 说明 |
|------|------|
| `-g` | 生成调试信息（默认级别 2） |
| `-g0` | 无调试信息 |
| `-g1` | 最少调试信息（仅函数名和外部变量） |
| `-g2` | 标准调试信息（局部变量、行号、类型定义） |
| `-g3` | 包含宏定义等额外调试信息 |
| `-ggdb` | 包含 GDB 扩展的调试信息（比 `-g` 更适合 GDB 调试） |
| `-g3 -gdwarf-5` | 指定 DWARF 版本（5 是最新标准） |

### 性能分析

| 选项 | 说明 |
|------|------|
| `-pg` | 为 `gprof` 性能分析工具插入 profiling 代码 |
| `-finstrument-functions` | 在每个函数入口/出口插入自定义回调 |

### 运行时检查（Sanitizers）

| 选项 | 说明 |
|------|------|
| `-fsanitize=address` | AddressSanitizer：检测**堆/栈/全局变量的越界和 use-after-free** |
| `-fsanitize=undefined` | UndefinedBehaviorSanitizer：检测未定义行为（整数溢出、空指针等） |
| `-fsanitize=thread` | ThreadSanitizer：检测数据竞争 |
| `-fsanitize=leak` | LeakSanitizer：检测内存泄漏 |
| `-fsanitize=memory` | MemorySanitizer：检测未初始化内存读取 |

```bash
# ASan 调试
gcc -g -fsanitize=address -o app app.c
./app  # 越界时打印详细报告

# UBSan 调试
gcc -g -fsanitize=undefined -o app app.c

# gprof 性能分析
gcc -pg -O2 -o app app.c
./app                # 生成 gmon.out
gprof app gmon.out   # 生成分析报告
```

## 警告选项

GCC 的警告系统分为多级，推荐以下组合：

| 选项 | 说明 |
|------|------|
| `-Wall` | 启用常用警告（并非 "all"） |
| `-Wextra` | 额外警告（原 `-W`） |
| `-Werror` | **将所有警告视为错误**，建议 CI 使用 |
| `-Wpedantic` | 严格遵循语言标准，禁止 GNU 扩展 |
| `-Wshadow` | 检测局部变量覆盖外层变量 |
| `-Wconversion` | 检测隐式类型转换可能丢失数据 |
| `-Wformat=2` | 加强 `printf`/`scanf` 格式字符串检查 |
| `-Wunused` | 检测未使用变量、函数、标签 |

```bash
# 推荐的生产级别警告组合
gcc -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wformat=2 -Werror -c foo.c

# 忽略特定警告
gcc -Wno-unused-parameter -c foo.c
```

## 预处理选项

| 选项 | 说明 |
|------|------|
| `-DNAME=VALUE` | 定义宏 `NAME` 为 `VALUE` |
| `-DNAME` | 定义宏 `NAME` 为 `1` |
| `-UNAME` | 取消宏 `NAME` 的定义 |
| `-I dir` | 添加头文件搜索路径 |
| `-include file` | 在编译前包含指定头文件 |
| `-imacros file` | 仅展开指定文件的宏，不包含其内容 |

```bash
# 条件编译
gcc -DDEBUG -DLOG_LEVEL=3 -c app.c

# 添加第三方头文件路径
gcc -I/usr/local/include -I../third-party/include -c app.c
```

## 链接选项

| 选项 | 说明 |
|------|------|
| `-L dir` | 添加库搜索路径 |
| `-l foo` | 链接 `libfoo.so` 或 `libfoo.a` |
| `-static` | 完全静态链接 |
| `-shared` | 生成共享库 (`.so`) |
| `-Wl,option` | 传递选项给链接器 `ld`（逗号分隔多个选项） |
| `-rdynamic` | 将所有符号导出到动态符号表（供 `dlopen` 反解） |
| `-pie` | 生成位置无关可执行文件（Position Independent Executable） |
| `-no-pie` | 生成固定地址可执行文件 |

```bash
# 手动指定库和路径
gcc -L/usr/lib/x86_64-linux-gnu -lm -lpthread app.o -o app

# 静态链接特定库，动态链接其他
gcc main.c -static-libgcc -Wl,-Bstatic -lfoo -Wl,-Bdynamic -lbar

# 传递多个链接器选项
gcc main.o -o app -Wl,-Map,output.map,--gc-sections

# 导出所有符号用于 dlopen
gcc -rdynamic main.c -ldl -o app
```

## 语言标准选项

| 标准 | `-std=` 选项 | 说明 |
|------|-------------|------|
| C89/C90 | `-std=c89` / `-std=c90` | ANSI C 标准 |
| C99 | `-std=c99` | 支持变长数组、单行注释、`restrict` |
| C11 | `-std=c11` | atomic、thread-local、泛型表达式 |
| C17 | `-std=c17` | 当前 C 标准的推荐版本 |
| C23 | `-std=c23` | C23 新特性（`#embed`, `typeof`, `constexpr`） |
| GNU C11 | `-std=gnu11` | C11 + GNU 扩展（默认） |
| C++98 | `-std=c++98` | 经典 C++ 标准 |
| C++11 | `-std=c++11` | auto、lambda、右值引用、智能指针 |
| C++14 | `-std=c++14` | 泛型 lambda、返回值推导、`make_unique` |
| C++17 | `-std=c++17` | 结构化绑定、if constexpr、`std::string_view` |
| C++20 | `-std=c++20` | 协程、概念、范围、`std::span` |
| C++23 | `-std=c++23` | `std::print`、`std::expected` |

```bash
# 使用特定标准
gcc -std=c17 -pedantic -o app app.c
g++ -std=c++20 -Wall -o app app.cpp

# 检查 GNU 扩展是否被使用
gcc -std=c17 -pedantic -o app app.c  # 使用 GNU 扩展时会警告
```

## 综合实战

```bash
# 生产级 C 构建（Release）
gcc -std=c17 \
    -O2 \
    -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Werror \
    -march=native \
    -flto \
    -o app \
    main.c module.c

# 开发调试构建
gcc -std=c17 \
    -O0 -g3 \
    -Wall -Wextra -Wpedantic \
    -fsanitize=address,undefined \
    -o app_debug \
    main.c module.c

# 构建共享库
gcc -std=c17 \
    -O2 -fPIC \
    -Wall -Wextra \
    -shared \
    -Wl,-soname,libfoo.so.1 \
    -o libfoo.so.1.0 \
    foo.c

# 构建静态库
gcc -std=c17 -O2 -c foo.c -o foo.o
ar rcs libfoo.a foo.o

# 使用优化分析
gcc -O3 -Q --help=optimizers | grep enabled
```

## 选项优先级

后出现的同类选项**覆盖**前面的：

```bash
# -O0 覆盖 -O2，最终是 -O0
gcc -O2 -O0 app.c -o app

# 多个 -D 后出现为最终值
gcc -DVER=1 -DVER=2 app.c -o app     # VER == 2
```
