GDB（GNU Debugger）是 Linux 下标准的命令行调试器，支持 C/C++/Go/Rust 等多种语言，可调试运行中的程序、分析 core dump、远程调试等。底层依赖 `ptrace` 系统调用实现进程控制。

## 编译准备

编译时必须加 `-g` 生成调试信息：

```bash
gcc -g -O0 -o program program.c
```

* `-g`：生成 DWARF 调试信息（行号、变量名、类型等）
* `-O0`：关闭优化，保证源码与指令一一对应
* 也可用 `-Og` 开启不影响调试的优化

检查调试信息是否存在：

```bash
readelf -S program | grep debug
file program | grep debug_info
```

## 启动 GDB

```bash
gdb program                # 调试可执行文件
gdb program core           # 分析 core dump
gdb program <pid>          # 附加到运行中进程
gdb -p <pid>               # 附加进程（无需 program）
gdb -tui program           # TUI 模式（源码窗口）
```

GDB 内重新加载程序：

```
(gdb) file program
(gdb) core-file core.1234
```

## 断点

```bash
break main                  # 函数入口
break program.c:42          # 文件 + 行号
break program.c:42 if x>10  # 条件断点
break *0x4005a0             # 地址断点
break malloc                # 库函数断点（需 debuginfo）

# 管理断点
info breakpoints            # 或 i b，列出所有断点
disable 2                   # 禁用编号 2
enable 2                    # 启用
delete 2                    # 删除编号 2
delete                      # 删除全部

# 临时断点
tbreak program.c:42         # 命中一次后自动删除

# 观察断点（watchpoint）
watch var                   # 变量被写入时中断
rwatch var                  # 变量被读取时中断
awatch var                  # 读写都中断

info watchpoints            # 列出所有观察断点
```

## 执行控制

```bash
run / r                     # 开始执行，可带参数
run arg1 arg2 < input.txt   # 带参数和重定向

continue / c                # 继续执行到下一个断点
next / n                    # 单步执行（跳过函数调用）
step / s                    # 单步执行（进入函数调用）
finish                      # 执行到当前函数返回
until 42                    # 执行到当前文件第 42 行

# 跳过或返回
skip function foo           # 跳过 foo 函数（不进入）
return                      # 强制从当前函数返回
return 0                    # 强制返回指定值
```

## 查看数据

```bash
# 打印变量
print / p x                 # 打印变量 x
p *ptr                      # 解引用指针
p arr[0]@10                 # 打印数组前 10 个元素（@ 是人工数组操作符）
p/x var                     # 十六进制格式
p/t var                     # 二进制格式
p/a var                     # 地址格式
p/c var                     # 字符格式
p/s str                     # 字符串格式

# 显示结构
ptype struct_name           # 打印类型定义
whatis var                  # 打印变量类型

# 自动显示（每次停止时打印）
display x                   # 每次停止打印 x
display/i $pc               # 每次显示下一条汇编指令
info display                # 列出 display 项
undisplay 1                 # 删除编号 1

# 内存查看
x/16x $rsp                  # 查看栈顶 16 个四字（十六进制）
x/s ptr                     # 以字符串形式查看内存
x/10i $pc                   # 反汇编当前地址 10 条指令
x/32bx addr                 # 以十六进制字节查看 32 字节
```

`x` 命令格式：`x/NFU addr`，N=数量，F=格式 (x=hex d=decimal s=string i=指令)，U=单位 (b=1 h=2 w=4 g=8 字节)。

## 栈帧

```bash
backtrace / bt              # 打印调用栈
bt full                     # 打印调用栈 + 所有局部变量
frame 2                     # 切换到第 2 帧
up                          # 上移一帧（调用者）
down                        # 下移一帧（被调用者）
info frame                  # 当前帧详细信息
info locals                 # 当前帧所有局部变量
info args                   # 当前帧函数参数
```

## 寄存器与汇编

```bash
info registers              # 或 i r，所有寄存器
p $rax                      # 打印 rax 寄存器
layout asm                  # TUI 汇编窗口
layout split                # TUI 源码 + 汇编
disassemble main            # 反汇编 main 函数
set disassembly-flavor intel # 设为 Intel 语法
```

## 修改变量

```bash
set var x = 100             # 修改变量 x
set var ptr = &y            # 修改指针
set {int}0x601000 = 42      # 直接修改内存地址的值
set $rax = 0                # 修改寄存器

# 修改二进制的实际内存（运行时）
call func()                 # 调用函数
```

## Core Dump 分析

```bash
# 确保 core dump 开启
ulimit -c unlimited
echo "/tmp/core.%e.%p" | sudo tee /proc/sys/kernel/core_pattern

# 用 GDB 加载
gdb program core.12345

# 常用分析命令
bt                          # 崩溃时的调用栈
bt full                     # 含局部变量
frame 0                     # 切到崩溃帧
info registers              # 崩溃时寄存器状态
p errno                     # 检查 errno
x/s $rip                    # 崩溃处的代码（字符串）
```

## TUI 模式

```bash
gdb -tui program            # 启动 TUI

# TUI 内快捷键
Ctrl+x a                    # 切换 TUI
Ctrl+x 2                    # 双窗口（源码 + 汇编）
Ctrl+x 1                    # 单窗口
Ctrl+x o                    # 焦点切换
Ctrl+l                      # 刷新屏幕

# 或使用命令
layout src                  # 源码窗口
layout asm                  # 汇编窗口
layout split                # 源码 + 汇编
layout regs                 # 寄存器窗口
tui reg float               # 显示浮点寄存器
```

TUI 模式下程序输出可能乱码，在命令前加 `tty` 重定向：

```bash
tty /dev/pts/2              # 把程序输出重定向到另一终端
```

## 脚本与自动化

```bash
# 初始化文件 ~/.gdbinit（自动加载）
set history save on
set print pretty on

# 项目级 .gdbinit（需手动启用）
echo "set auto-load local-gdbinit on" >> ~/.gdbinit

# 批处理执行
gdb -batch -ex "bt" -ex "quit" program core

# GDB 内执行脚本
source commands.gdb
```

`.gdbinit` 常用配置：

```bash
set pagination off             # 不分页
set print pretty on            # 结构体格式化显示
set print array on             # 数组格式化显示
set print array-indexes on     # 数组显示下标
set history save on            # 保存命令历史
set disassembly-flavor intel   # Intel 汇编语法
```

## 远程调试

```bash
# 目标机
gdbserver :1234 ./program

# 开发机
gdb ./program
(gdb) target remote 192.168.1.100:1234
```

## 常用调试场景

```bash
# 定位段错误
gdb program
(gdb) run
# Program received signal SIGSEGV
(gdb) bt                     # 崩溃时刻的调用栈直接指出元凶

# 跟踪子进程
(gdb) set follow-fork-mode child    # 跟踪子进程
(gdb) set detach-on-fork off        # 父子都调试（info inferiors 切换）

# 多线程
(gdb) info threads                  # 列出所有线程
(gdb) thread 3                      # 切换到线程 3
(gdb) thread apply all bt           # 所有线程的调用栈
(gdb) set scheduler-locking on      # 只运行当前线程

# 监视内存泄漏点
(gdb) break malloc
(gdb) commands
> silent
> printf "malloc(%d) from ", $rdi
> bt 3
> continue
> end

# 断点处自动执行命令序列
(gdb) break foo.c:42
(gdb) commands 1
> print x
> print y
> continue
> end
```

## 命令速查

| 类别 | 命令 |
|------|------|
| 断点 | `b` `tbreak` `enable` `disable` `delete` `watch` |
| 执行 | `r` `c` `n` `s` `finish` `until` `return` |
| 查看 | `p` `x` `display` `ptype` `whatis` |
| 栈 | `bt` `frame` `up` `down` `info locals` `info args` |
| 寄存器 | `info registers` `p $rax` `layout regs` |
| 修改 | `set var` `set {type}addr` `call` |
| 信息 | `info break` `info threads` `info inferiors` `info shared` |
| 控制 | `quit` `file` `core-file` `directory` `source` |
