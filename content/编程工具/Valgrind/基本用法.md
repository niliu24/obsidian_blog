> Valgrind 各工具的使用方法、关键选项解读和实战示例。以 Memcheck（内存错误检测）为核心，覆盖 Helgrind（线程竞争）、Callgrind（性能剖析）、Massif（堆内存剖析）。

## Memcheck（默认工具）

Memcheck 是 Valgrind 使用最广泛的工具，也是 **默认工具**（不指定 `--tool` 时自动启用）。它拦截所有内存读写操作，在合成 CPU 的 IR 层面对每一条 load/store 指令插桩，检测以下错误类型：

| 检测类型 | 说明 |
|----------|------|
| **堆缓冲区溢出** | 访问超出 `malloc` / `new` 分配的范围 |
| **Use-After-Free** | 释放后继续访问堆内存（dangling pointer） |
| **Double Free** | 重复释放同一块内存 |
| **内存泄漏** | 已丢失指针的堆内存（`malloc` 后无对应 `free`） |
| **未初始化值使用** | 读取未赋值的栈/堆变量作为分支条件或输出 |
| **Invalid Free** | `free` 传入非 malloc 返回的地址 |
| **重叠拷贝** | `memcpy` 的 src 和 dst 区域重叠（需改用 `memmove`） |
| **栈访问越界** | 栈上数组/局部变量的越界访问 |
| **系统调用参数** | 传给系统调用的指针无效或长度错误 |

### 关键选项

```bash
# 最常用组合：完整泄漏报告 + 追踪未初始化来源
valgrind --leak-check=full --show-leak-kinds=all --track-origins=yes ./program

# 输出到文件
valgrind --leak-check=full --log-file=valgrind.log ./program

# 抑制已知误报（如 glibc 内部泄漏）
valgrind --suppressions=my.supp ./program

# XML 输出（适合集成到 CI pipeline）
valgrind --xml=yes --xml-file=out.xml ./program

# 只报告错误，隐藏泄漏总结
valgrind --leak-check=no ./program

# 控制栈回溯深度
valgrind --num-callers=30 ./program
```

#### `--leak-check` 模式

| 级别 | 说明 |
|------|------|
| `no` | 不检测泄漏 |
| `summary` | 仅报告泄漏总结（多少个块、多少字节） |
| `full` | 详细报告每个泄漏的分配点（默认） |

#### 泄漏类型

| 类型 | 含义 |
|------|------|
| **Definitely Lost** | 指针完全丢失，内存不可达——**必须修复** |
| **Indirectly Lost** | 因某个 Definitely Lost 的根节点导致整棵结构树不可达（修复根节点即可） |
| **Possibly Lost** | 指针指向结构体内部某个字段而非头部，无法确定是否需要释放 |
| **Still Reachable** | 程序结束时指针仍指向堆内存（全局变量未释放），进程退出后 OS 会回收，但应视作代码质量问题 |

### 输出解读

Memcheck 错误报告格式：

```

==12345==    at 0x4006E1: main (example.c:5)  # 栈回溯——错误发生位置
==12345==    by 0x4E3F082: ...                  # 调用链

==12345==    at 0x4C2B0E0: malloc (vg_replace_malloc.c:299)
==12345==    by 0x4006D2: main (example.c:4)
```

### 示例：检测内存泄漏

```c
// leak.c
#include <stdlib.h>
#include <stdio.h>

void leak_memory(void) {
    int *p = (int *)malloc(10 * sizeof(int));
    // 忘记 free(p) —— 泄漏 40 字节
}

int main(void) {
    leak_memory();
    return 0;
}
```

```bash
$ gcc -g -o leak leak.c
$ valgrind --leak-check=full --show-leak-kinds=all ./leak
```

### 抑制文件

某些系统库或第三方库包含已知的内存问题，每次运行都报告会造成噪音。抑制文件（`.supp`）告诉 Valgrind 忽略特定类型的错误。

```bash
# 生成抑制项：运行后要求 Valgrind 输出抑制模板
valgrind --gen-suppressions=all ./program 2>&1 | grep -A 100 "^==" | head -200

# 或使用 --gen-suppressions=yes 在每次报告后交互式询问
valgrind --gen-suppressions=yes ./program
```

## Helgrind（线程错误检测）

Helgrind 检测多线程程序中的 **Data Race**（数据竞争）、**锁顺序违反**（Lock Order Violation）和 **POSIX 线程 API 误用**。

### 工作原理

Helgrind 跟踪每个线程的加锁/解锁序列，构建 **锁集（Lock-Set）** 和 **Happens-Before 图**，在共享内存访问时判断是否存在两条并发路径同时访问同一位置且至少一条为写操作。

### 关键选项

```bash
# 完整历史记录
valgrind --tool=helgrind --history-level=full ./program

# 启用/禁用锁顺序检测（默认启用）
valgrind --tool=helgrind --track-lockorders=yes ./program
```

### 示例：检测 Data Race

```c
// race.c
#include <pthread.h>
#include <stdio.h>

int counter = 0;  // 共享全局变量，未加锁

void *worker(void *arg) {
    for (int i = 0; i < 100000; i++)
        counter++;  // 非原子操作，存在 Data Race
    return NULL;
}

int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker, NULL);
    pthread_create(&t2, NULL, worker, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("counter = %d\n", counter);
    return 0;
}
```

```bash
$ gcc -g -pthread -o race race.c
$ valgrind --tool=helgrind ./race
```

输出亮点：

```
==12345== Possible data race during write of size 4 at 0x60104C
==12345==    at 0x40055F: worker (race.c:7)
==12345==  This conflicts with a previous write of size 4 at 0x60104C
==12345==    at 0x40055F: worker (race.c:7)
==12345==  Address 0x60104C is in data section "counter"
```

### 常见检测项

| 检测项 | 说明 |
|--------|------|
| Data Race | 多线程并发读写同一内存位置，至少一方写，且无同步 |
| Lock Order Violation | 不同线程以不一致的顺序加锁（潜在死锁） |
| 重复解锁 | 对已解锁的 mutex 再次 `pthread_mutex_unlock` |
| 未初始化锁 | 使用未调用 `pthread_mutex_init` 的锁 |
| 线程/锁不匹配 | 如跨线程对 `PTHREAD_MUTEX_ERRORCHECK` 解锁 |

## Callgrind（缓存/分支剖析器）

Callgrind 在 VEX IR 中插入计数指令，统计每条指令的执行次数、函数调用关系和缓存命中率，提供比 `gprof` 精确得多的指令级 Profile。

### 关键选项

```bash
# 收集指令级信息
valgrind --tool=callgrind --dump-instr=yes ./program

# 收集分支预测信息
valgrind --tool=callgrind --collect-jumps=yes ./program

# 模拟缓存行为
valgrind --tool=callgrind --cache-sim=yes ./program

# 按文件/函数分离输出
valgrind --tool=callgrind --separate-threads=yes ./program

# 手动触发 dump（运行时向子进程发 SIGUSR1）
kill -USR1 <pid>
```

### 输出文件

Callgrind 默认生成 `callgrind.out.<PID>`（纯文本格式）。用以下工具可视化：

| 工具 | 安装 | 用途 |
|------|------|------|
| **kcachegrind** | `sudo apt install kcachegrind` | GUI：调用图、Callee Map、源码标注 |
| **gprof2dot** | `pip install gprof2dot` | 生成 Graphviz 调用图 |
| **qcachegrind** | macOS 替代 | 与 kcachegrind 功能相同 |

```bash
# GUI 分析
kcachegrind callgrind.out.12345

# 命令行查看调用次数（无图形时用 callgrind_annotate）
callgrind_annotate callgrind.out.12345

# 源码级别标注（需编译时加 -g）
callgrind_annotate --auto=yes callgrind.out.12345
```

### 示例：Profile 一个计算函数

```c
// compute.c
#include <stdlib.h>
#include <stdio.h>

double compute(int n) {
    double sum = 0.0;
    for (int i = 1; i <= n; i++)
        sum += 1.0 / (double)i;
    return sum;
}

int main(void) {
    double result = 0.0;
    for (int i = 0; i < 10000; i++)
        result += compute(10000);
    printf("result = %f\n", result);
    return 0;
}
```

```bash
$ gcc -g -O0 -o compute compute.c
$ valgrind --tool=callgrind --dump-instr=yes ./compute
$ kcachegrind callgrind.out.*
```

### kcachegrind 核心视图

| 视图 | 说明 |
|------|------|
| **Flat Profile** | 函数总指令数降序排列 |
| **Call Graph** | 函数调用关系 + 指令数占比（有向图，线宽表示调用频率） |
| **Callee Map** | 矩形面积编码函数相对开销（类似火焰图） |
| **Source Annotation** | 逐行显示每条 C 语句对应的指令数和缓存事件 |

## Massif（堆内存剖析器）

Massif 随时间记录堆内存分配/释放情况，帮助定位 **峰值内存**、**不必要的分配** 和 **内存增长趋势**。默认只追踪堆，可通过 `--pages-as-heap=yes` 追踪匿名 mmap。

### 关键选项

```bash
# 以分配的字节数为时间单位（更精确）
valgrind --tool=massif --time-unit=B ./program

# 详细采样频率（每 10 次分配/释放记录一次详细快照）
valgrind --tool=massif --detailed-freq=10 ./program

# 内存分配阈值（忽略小分配导致的快照）
valgrind --tool=massif --threshold=0.1 ./program

# Massif + 页作为堆（追踪 mmap 分配）
valgrind --tool=massif --pages-as-heap=yes ./program
```

### 输出与可视化

Massif 生成 `massif.out.<PID>`，使用两个工具查看：

```bash
# 文本图形（无依赖）
ms_print massif.out.12345

# GUI 可视化
sudo apt install massif-visualizer
massif-visualizer massif.out.12345
```

### 示例：追踪堆增长

```c
// heap.c
#include <stdlib.h>
#include <string.h>

int main(void) {
    // 阶段 1：分配 1 MB
    char *a = (char *)malloc(1024 * 1024);
    memset(a, 0, 1024 * 1024);

    // 阶段 2：分配 2 MB
    char *b = (char *)malloc(2 * 1024 * 1024);
    memset(b, 0, 2 * 1024 * 1024);

    free(a);

    // 阶段 3：分配 3 MB
    char *c = (char *)malloc(3 * 1024 * 1024);
    memset(c, 0, 3 * 1024 * 1024);

    free(b);
    free(c);
    return 0;
}
```

```bash
$ gcc -g -o heap heap.c
$ valgrind --tool=massif --time-unit=B ./heap
$ ms_print massif.out.*
```

`ms_print` 输出包含 ASCII 火焰图和时间线，显示每个快照点的堆使用量、峰值位置和对应的分配调用栈。

## 工具选择指南

| 场景 | 推荐工具 | 替代方案 |
|------|----------|----------|
| 程序崩溃 / 段错误 | **Memcheck** | AddressSanitizer（更快但需重编译） |
| 结果随机不对 | **Memcheck**（未初始化值） | — |
| 多线程下偶发崩溃 | **Helgrind** / **DRD** | ThreadSanitizer（更快但需重编译） |
| 性能不符合预期 | **Callgrind** + **kcachegrind** | perf（系统级）、gprof（已过时） |
| 内存占用持续增长 | **Massif** | heaptrack（更现代，KDE 生态） |
| 堆分配模式分析 | **DHAT** | — |
| 调试死锁 | **Helgrind** | — |

> **注意**: Valgrind 在合成 CPU 上运行，性能开销较大。生产环境或大型程序建议先用 **AddressSanitizer** / **ThreadSanitizer**（编译期插桩，开销 2-4x），再用 Valgrind 做深度排查。
