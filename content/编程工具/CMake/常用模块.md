> CMake 内置了大量**模块**（Modules）用于查找外部依赖、集成测试框架、生成安装包等。模块通过 `include()` 或 `find_package()` 加载，大部分位于 `<CMAKE_ROOT>/Modules/` 目录下。

## find_package 机制

`find_package` 是 CMake 查找和管理外部依赖的核心命令，有两种工作模式：

### MODULE 模式

CMake 查找名为 `Find<PackageName>.cmake` 的模块文件，由 CMake 自身或项目提供。

```cmake
# MODULE 模式（默认，当存在 Find*.cmake 时）
find_package(Boost 1.75 REQUIRED COMPONENTS filesystem system)
```

### CONFIG 模式

依赖包自身提供 `<PackageName>Config.cmake` 或 `<lower-name>-config.cmake` 文件，包含目标的完整定义。

```cmake
# CONFIG 模式（显式指定）
find_package(fmt CONFIG REQUIRED)

# CMake 在以下路径查找 Config 文件：
#   <prefix>/lib/cmake/<PackageName>/
#   <prefix>/share/<PackageName>/
#   <prefix>/lib/<PackageName>-cmake/
```

| 模式 | 查找文件 | 适用场景 |
|------|----------|----------|
| **MODULE** | `Find<Name>.cmake` | 系统包管理器安装的库（如 Boost、Python） |
| **CONFIG** | `<Name>Config.cmake` | 自身安装的库（如 fmt、spdlog、Eigen3） |

### 常用参数

```cmake
find_package(Pkg REQUIRED)                 # 必需，找不到即报错
find_package(Pkg QUIET)                    # 不打印找不到的消息
find_package(Pkg REQUIRED COMPONENTS A B)  # 需要特定组件

# 指定搜索路径（优先级高于默认路径）
set(CMAKE_PREFIX_PATH "/opt/mylib;/custom/path")

# 版本要求
find_package(Pkg 3.2 EXACT)                # 精确版本
find_package(Pkg 3.0)                      # >= 3.0

# 可选依赖
find_package(Pkg)
if(Pkg_FOUND)
    target_link_libraries(myapp PRIVATE Pkg::Pkg)
endif()
```

### 查找结果变量

每个 `find_package` 调用会设置以下变量：

| 变量 | 说明 |
|------|------|
| `<Pkg>_FOUND` | 是否找到 |
| `<Pkg>_INCLUDE_DIRS` | 包含路径（MODULE 模式） |
| `<Pkg>_LIBRARIES` | 库文件列表（MODULE 模式） |
| `<Pkg>_VERSION` | 找到的版本号 |
| `<Pkg>_DIR` | Config 文件所在目录 |

> **Modern CMake 最佳实践**：优先使用 **Imported Targets**（如 `Boost::filesystem`、`fmt::fmt`）而非变量（`${Boost_INCLUDE_DIRS}`、`${Boost_LIBRARIES}`），因为目标会自动传播包含路径、编译定义等传递属性。

## 常用 Find 模块

### FindBoost

```cmake
find_package(Boost 1.75 REQUIRED COMPONENTS
    filesystem
    system
    program_options
)

if(Boost_FOUND)
    # Modern: 使用 Imported Targets（Boost 1.70+）
    target_link_libraries(myapp PRIVATE
        Boost::filesystem
        Boost::system
        Boost::program_options
    )

    # Legacy: 使用变量
    # target_include_directories(myapp PRIVATE ${Boost_INCLUDE_DIRS})
    # target_link_libraries(myapp PRIVATE ${Boost_LIBRARIES})
endif()

# 调试变量
message(STATUS "Boost version: ${Boost_VERSION}")
message(STATUS "Boost libraries: ${Boost_LIBRARIES}")
```

| 变量 | 说明 |
|------|------|
| `Boost_FOUND` | 是否找到 |
| `Boost_INCLUDE_DIRS` | Boost 头文件路径 |
| `Boost_LIBRARIES` | 库文件列表 |
| `Boost_VERSION` | 版本号（如 107500） |
| `Boost_<COMPONENT>_FOUND` | 特定组件是否找到 |

### FindOpenGL

```cmake
find_package(OpenGL REQUIRED)
find_package(GLFW3 REQUIRED)
find_package(GLEW REQUIRED)

target_link_libraries(myapp PRIVATE
    OpenGL::GL
    OpenGL::GLU
    glfw
    GLEW::GLEW
)
```

### FindThreads

```cmake
find_package(Threads REQUIRED)

target_link_libraries(myapp PRIVATE Threads::Threads)

# 自动添加 -pthread 编译和链接标志
```

### FindPython

```cmake
# FindPython3 / FindPython2 / FindPython（CMake 3.12+）
find_package(Python3 REQUIRED COMPONENTS Interpreter Development)

# Python 解释器
execute_process(COMMAND ${Python3_EXECUTABLE} -c "print('hello')")

# C++ 嵌入 Python
target_link_libraries(myapp PRIVATE Python3::Python)

# Python 扩展模块
pybind11_add_module(mymodule src/bindings.cpp)
target_link_libraries(mymodule PRIVATE pybind11::module)
```

| 变量 | 说明 |
|------|------|
| `Python3_EXECUTABLE` | Python 解释器路径 |
| `Python3_INCLUDE_DIRS` | Python.h 包含路径 |
| `Python3_LIBRARIES` | Python 库 |
| `Python3_VERSION` | Python 版本 |

### PkgConfig 集成

对于没有 CMake 支持的库，可以通过 `pkg-config` 查找：

```cmake
find_package(PkgConfig REQUIRED)

# 查找库
pkg_check_modules(LIBAV REQUIRED
    libavcodec
    libavformat
    libavutil
)

# 使用变量
target_include_directories(myapp PRIVATE ${LIBAV_INCLUDE_DIRS})
target_link_libraries(myapp PRIVATE ${LIBAV_LIBRARIES})
target_compile_options(myapp PRIVATE ${LIBAV_CFLAGS_OTHER})

# 存在性检查
pkg_check_modules(FFMPEG libavcodec>=58 libavformat>=58)

# 更简洁的方式（CMake 3.6+ 自动生成 IMPORTED 目标）
pkg_check_modules(LIBAV IMPORTED_TARGET REQUIRED libavcodec libavformat)
target_link_libraries(myapp PRIVATE PkgConfig::LIBAV)
```

## FetchContent — 配置时下载依赖

`FetchContent` 允许在 CMake **配置阶段**下载并构建依赖，无需手动安装。适用于小规模依赖和示例项目。

```cmake
include(FetchContent)

# 声明依赖
FetchContent_Declare(
    fmt
    GIT_REPOSITORY https://github.com/fmtlib/fmt.git
    GIT_TAG 10.1.1
    GIT_SHALLOW TRUE                     # 浅克隆，减少下载量
)

FetchContent_Declare(
    nlohmann_json
    URL https://github.com/nlohmann/json/releases/download/v3.11.2/json.tar.xz
    URL_HASH SHA256=3a5d36f9c1e16b10d5d0e70b1389f51e
)

FetchContent_Declare(
    googletest
    GIT_REPOSITORY https://github.com/google/googletest.git
    GIT_TAG v1.14.0
    GIT_SHALLOW TRUE
    OVERRIDE_FIND_PACKAGE                # 拦截 find_package(GTest) 调用
)

# 下载并引入依赖（CMake 3.14+）
FetchContent_MakeAvailable(fmt nlohmann_json googletest)

# 之后可以直接使用目标
target_link_libraries(myapp PRIVATE fmt::fmt nlohmann_json::nlohmann_json)
target_link_libraries(mytests PRIVATE GTest::gtest GTest::gtest_main)
```

| 命令 | 说明 |
|------|------|
| `FetchContent_Declare` | 声明一个可获取的内容项（名称、仓库/URL、标签、哈希） |
| `FetchContent_MakeAvailable` | 下载、配置并添加依赖到构建（CMake 3.14+） |
| `FetchContent_Populate` | 仅下载，不添加构建（旧式 API） |
| `FetchContent_GetProperties` | 查询内容项的状态和路径 |

**注意事项**：

* FetchContent 调用 `add_subdirectory()` 引入依赖，可能会引入依赖的外部依赖
* 不同项目可能依赖不同版本的同一库——FetchContent 会去重
* 对于大型/稳定依赖，建议使用系统包管理器而非 FetchContent

## CTest — 测试

CTest 是 CMake 集成的测试工具，与 `add_test` 和 `enable_testing` 配合使用。

```cmake
# 顶层 CMakeLists.txt 中启用测试
enable_testing()
# 或在子目录中用 include(CTest)

# === 简单测试 ===
add_test(NAME test_math COMMAND myapp --test-math)
add_test(NAME test_render COMMAND myapp --test-render)

# === 基于配置的测试 ===
add_test(NAME unit_tests COMMAND test_runner)
set_tests_properties(unit_tests PROPERTIES
    TIMEOUT 30                   # 超时 30 秒
    WORKING_DIRECTORY "${CMAKE_CURRENT_BINARY_DIR}"
    ENVIRONMENT "TEST_DIR=${CMAKE_CURRENT_SOURCE_DIR}/testdata"
    LABELS "unit;core"
)

# === 使用 GTest 的便捷宏（需 find_package(GTest)） ===
include(GoogleTest)
find_package(GTest REQUIRED)

add_executable(test_core test_core.cpp)
target_link_libraries(test_core PRIVATE GTest::gtest GTest::gtest_main mylib)
gtest_discover_tests(test_core)            # 自动注册 GTest 测试用例
# gtest_add_tests(test_core)               # 旧式方法

# === 基于配置的跳过 ===
add_test(NAME integration_test COMMAND test_integration)
set_tests_properties(integration_test PROPERTIES
    SKIP_RETURN_CODE 77                    # 返回 77 表示跳过（与 Autotools 兼容）
)
```

### CTest 命令行

```bash
# 运行所有测试
ctest --test-dir build

# 并行运行
ctest --test-dir build -j8

# 输出详细信息
ctest --test-dir build -V
ctest --test-dir build -VV

# 按标签过滤
ctest --test-dir build -L unit      # 仅运行 unit 标签
ctest --test-dir build -LE slow     # 排除 slow 标签

# 按名称过滤
ctest --test-dir build -R test_math

# 失败重试
ctest --test-dir build --repeat-until-fail 3

# 输出 JUnit 格式
ctest --test-dir build --output-junit results.xml
```

## CPack — 打包

CPack 从 CMake 构建产物生成安装包（deb、rpm、tar.gz、NSIS、DMG 等）。

```cmake
# === 项目信息（CPack 从中读取） ===
set(PROJECT_NAME "MyApp")
set(PROJECT_VERSION "2.1.0")

# === CPack 配置 ===
include(CPack)

# 或自定义配置
set(CPACK_PACKAGE_NAME "MyApp")
set(CPACK_PACKAGE_VERSION ${PROJECT_VERSION})
set(CPACK_PACKAGE_VENDOR "My Company")
set(CPACK_PACKAGE_DESCRIPTION_SUMMARY "A useful application")
set(CPACK_PACKAGE_CONTACT "support@mycompany.com")
set(CPACK_PACKAGE_FILE_NAME "${CPACK_PACKAGE_NAME}-${CPACK_PACKAGE_VERSION}-${CMAKE_SYSTEM_PROCESSOR}")

# 各生成器特定配置
set(CPACK_GENERATOR "DEB;TGZ")
set(CPACK_DEBIAN_PACKAGE_DEPENDS "libssl-dev (>= 1.1), zlib1g-dev (>= 1.2)")
set(CPACK_DEBIAN_PACKAGE_SECTION "devel")

set(CPACK_NSIS_DISPLAY_NAME "MyApp Installer")
set(CPACK_NSIS_INSTALL_ROOT "$PROGRAMFILES64")

# 包含 CPack 必须放在最后
include(CPack)
```

打包：`cpack --config build/CPackConfig.cmake` 或 `cmake --build build --target package`。

## ExternalProject — 构建时下载依赖

与 FetchContent 在配置阶段下载不同，`ExternalProject` 在**构建阶段**下载并构建外部项目。

```cmake
include(ExternalProject)

ExternalProject_Add(
    libfoo
    GIT_REPOSITORY https://github.com/example/libfoo.git
    GIT_TAG v2.0
    GIT_SHALLOW TRUE
    PREFIX ${CMAKE_BINARY_DIR}/external/libfoo
    CMAKE_ARGS
        -DCMAKE_INSTALL_PREFIX=<INSTALL_DIR>
        -DBUILD_SHARED_LIBS=ON
    BUILD_ALWAYS OFF                    # 已构建则不重新构建
    LOG_DOWNLOAD ON
    LOG_CONFIGURE ON
    LOG_BUILD ON
)

# 使主项目依赖 ExternalProject
add_dependencies(myapp libfoo)
```

| API | FetchContent | ExternalProject |
|-----|-------------|----------------|
| **阶段** | 配置时（Configure） | 构建时（Build） |
| **集成方式** | `add_subdirectory()` | 独立的构建步骤 |
| **目标可见** | 配置时即知 | 需手动查找 |
| **适合场景** | 源码级组件 | 大型外部依赖、交叉编译 |
| **支持 URL** | 是 | 是 |
| **支持 Git** | 是 | 是 |

## 实用模块

### GNUInstallDirs

```cmake
include(GNUInstallDirs)

# 设置标准的 GNU 安装路径变量
install(TARGETS mylib
    LIBRARY DESTINATION ${CMAKE_INSTALL_LIBDIR}    # → lib, lib64, lib/x86_64-linux-gnu
    BIN DESTINATION ${CMAKE_INSTALL_BINDIR}        # → bin
    INCLUDES DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}  # → include
)

# 跨平台的标准路径
message(STATUS "Install libdir: ${CMAKE_INSTALL_LIBDIR}")
message(STATUS "Install bindir: ${CMAKE_INSTALL_BINDIR}")
```

| 变量 | 典型值 |
|------|--------|
| `CMAKE_INSTALL_BINDIR` | `bin` |
| `CMAKE_INSTALL_LIBDIR` | `lib` / `lib64` / `lib/x86_64-linux-gnu` |
| `CMAKE_INSTALL_INCLUDEDIR` | `include` |
| `CMAKE_INSTALL_DATADIR` | `share` |
| `CMAKE_INSTALL_SYSCONFDIR` | `etc` |

### CheckCXXCompilerFlag

```cmake
include(CheckCXXCompilerFlag)

# 检查编译器是否支持某个标志
check_cxx_compiler_flag("-std=c++17" CXX17_SUPPORTED)
if(CXX17_SUPPORTED)
    set(CMAKE_CXX_STANDARD 17)
endif()

check_cxx_compiler_flag("-fvisibility=hidden" HAS_VISIBILITY)
if(HAS_VISIBILITY)
    set(CMAKE_CXX_VISIBILITY_PRESET hidden)
endif()

# 类似模块：CheckCCompilerFlag、CheckIncludeFile、CheckLibraryExists
```

### GenerateExportHeader

自动生成**符号可见性控制**的导出宏头文件。

```cmake
include(GenerateExportHeader)

add_library(mylib SHARED src/mylib.cpp)
generate_export_header(mylib
    BASE_NAME mylib
    EXPORT_MACRO_NAME MYLIB_EXPORT
    EXPORT_FILE_NAME ${CMAKE_CURRENT_BINARY_DIR}/include/mylib_export.h
    STATIC_DEFINE MYLIB_STATIC_BUILD
)

target_include_directories(mylib
    PUBLIC
        $<BUILD_INTERFACE:${CMAKE_CURRENT_BINARY_DIR}/include>
)
```

生成的 `mylib_export.h`：

```c
#ifndef MYLIB_EXPORT_H
#define MYLIB_EXPORT_H

#ifdef MYLIB_STATIC_BUILD
#  define MYLIB_EXPORT
#elif defined(mylib_EXPORTS)  // CMake 自动定义
#  define MYLIB_EXPORT __attribute__((visibility("default")))
#else
#  define MYLIB_EXPORT __attribute__((visibility("default")))
#endif

#endif
```

使用：

```cpp
#include <mylib_export.h>

class MYLIB_EXPORT MyClass {
    void publicMethod();
};
```

### CTest + Coverage（Code Coverage）

```cmake
if(CMAKE_BUILD_TYPE STREQUAL "Debug" OR CMAKE_BUILD_TYPE STREQUAL "Coverage")
    option(ENABLE_COVERAGE "Enable coverage reporting" ON)
endif()

if(ENABLE_COVERAGE)
    include(CheckCXXCompilerFlag)
    check_cxx_compiler_flag("--coverage" HAS_COVERAGE)
    if(HAS_COVERAGE)
        set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} --coverage -O0 -g")
        set(CMAKE_EXE_LINKER_FLAGS "${CMAKE_EXE_LINKER_FLAGS} --coverage")
    endif()
endif()
```

## 完整示例：综合使用

```cmake
cmake_minimum_required(VERSION 3.20)
project(MyProject VERSION 1.0.0 LANGUAGES CXX)

# === 选项 ===
option(BUILD_TESTS "Build tests" ON)
option(BUILD_EXAMPLES "Build examples" ON)
option(ENABLE_COVERAGE "Enable code coverage" OFF)

# === 编译标准 ===
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# === 查找依赖 ===
# CONFIG 模式
find_package(fmt 10 CONFIG REQUIRED)

# MODULE 模式
find_package(Boost 1.75 REQUIRED COMPONENTS filesystem system)
find_package(Threads REQUIRED)
find_package(Python3 COMPONENTS Interpreter)

# pkg-config 回退
if(NOT Python3_FOUND)
    find_package(PkgConfig)
    if(PkgConfig_FOUND)
        pkg_check_modules(Python3 IMPORTED_TARGET python3-embed)
    endif()
endif()

# === FetchContent ===
include(FetchContent)

FetchContent_Declare(
    nlohmann_json
    GIT_REPOSITORY https://github.com/nlohmann/json.git
    GIT_TAG v3.11.3
    GIT_SHALLOW TRUE
)
FetchContent_MakeAvailable(nlohmann_json)

# === 主库 ===
add_library(mycore src/core.cpp src/utils.cpp)
target_include_directories(mycore
    PUBLIC
        $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
        $<INSTALL_INTERFACE:include>
)
target_link_libraries(mycore
    PUBLIC fmt::fmt nlohmann_json::nlohmann_json
    PRIVATE Boost::filesystem Boost::system Threads::Threads
)

# === 示例 ===
if(BUILD_EXAMPLES)
    add_executable(myapp src/main.cpp)
    target_link_libraries(myapp PRIVATE mycore)
endif()

# === 测试 ===
if(BUILD_TESTS)
    enable_testing()

    FetchContent_Declare(
        googletest
        GIT_REPOSITORY https://github.com/google/googletest.git
        GIT_TAG v1.14.0
        GIT_SHALLOW TRUE
        OVERRIDE_FIND_PACKAGE
    )
    FetchContent_MakeAvailable(googletest)

    add_executable(test_core test/test_core.cpp)
    target_link_libraries(test_core PRIVATE mycore GTest::gtest GTest::gtest_main)

    include(GoogleTest)
    gtest_discover_tests(test_core)

    add_test(NAME integration_test COMMAND test_integration)
    set_tests_properties(integration_test PROPERTIES TIMEOUT 60)
endif()

# === 安装 ===
include(GNUInstallDirs)
install(TARGETS mycore
    EXPORT MyProjectTargets
    LIBRARY DESTINATION ${CMAKE_INSTALL_LIBDIR}
    ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR}
)
install(DIRECTORY include/ DESTINATION ${CMAKE_INSTALL_INCLUDEDIR})
install(EXPORT MyProjectTargets
    FILE MyProjectTargets.cmake
    DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/MyProject
)

# === 打包 ===
set(CPACK_PACKAGE_NAME "MyProject")
set(CPACK_PACKAGE_VERSION ${PROJECT_VERSION})
set(CPACK_GENERATOR "TGZ;DEB")
include(CPack)
```
