Git 是 Linus Torvalds 开发的分布式版本控制系统。每个开发者的本地仓库都是一个完整的版本库，包含全部历史记录，不依赖中央服务器即可进行提交、分支、查看历史等操作。

## 核心概念

Git 将文件状态分为三个区域，对应三种逻辑 " 树 "：

```
工作目录 (Working Dir)       暂存区 (Staging / Index)      版本库 (Repository)
      │                              │                         │
      │    git add                    │    git commit           │
      │ ──────────────────────────→  │ ──────────────────────→ │
      │                              │                         │
      │←─────────────────────────────│←────────────────────────│
              git checkout / restore       git reset / restore --staged
```

| 概念 | 说明 |
|------|------|
| Working Directory | 当前工作目录中的文件，直接编辑的文件 |
| Staging Area (Index) | `git add` 后的快照，决定下一次 commit 包含什么 |
| Repository | `.git` 目录，存储所有提交历史、分支、标签等元数据 |
| HEAD | 指向当前所在分支（或某次 commit）的指针 |
| Branch | 指向某次 commit 的可移动指针，代表一条独立的开发线 |
| Remote | 远程仓库引用，如 `origin/main` 表示远程 `origin` 的 `main` 分支 |

## 基本配置

```bash
git config --global user.name "Your Name"
git config --global user.email "your@email.com"
git config --global core.editor vim
git config --global init.defaultBranch main
git config --global alias.co checkout    # 常用别名
git config --global alias.br branch
git config --global alias.st status
git config --global alias.lg "log --oneline --graph --all"
git config --list                        # 查看所有配置
```

配置文件位置：全局 `~/.gitconfig`，项目级 `.git/config`，系统级 `/etc/gitconfig`。

## 仓库操作

```bash
git init                    # 初始化本地仓库
git clone <url>             # 克隆远程仓库
git clone -b <branch> <url> # 克隆指定分支
git clone --depth=1 <url>   # 浅克隆（仅最新提交，节省空间和时间）

# 查看仓库状态
git status                  # 显示工作区和暂存区状态
git status -s               # 简短输出
git log                     # 查看提交历史
```

## 记录变更

```bash
git add <file>              # 将文件加入暂存区
git add -p <file>           # 交互式选择部分修改加入暂存区
git add -u                  # 仅暂存已跟踪文件的修改（不包含新文件）
git add -A                  # 暂存所有变更（包含新文件、修改、删除）

git commit -m "message"     # 提交暂存区内容
git commit -am "message"    # 跳过 add，直接提交所有已跟踪文件的变更
git commit --amend          # 修改最近一次提交（合并暂存区变更，重写 message）
```

### Commit Message 规范

```
<type>(<scope>): <subject>

<body>

<footer>
```

常见 type：`feat`（新功能）、`fix`（修复）、`docs`（文档）、`refactor`（重构）、`test`（测试）、`chore`（构建/工具）。

## 查看历史

```bash
git log                     # 完整提交历史
git log --oneline           # 一行一条
git log --graph --all       # ASCII 图显示分支拓扑
git log --author="name"     # 按作者过滤
git log --since="2026-01-01"  # 按日期过滤
git log -S"keyword"         # 搜索新增/删除某关键词的提交（pickaxe）
git log -p <file>           # 显示某文件的逐次变更详情

git show <commit>           # 显示某次提交的详细信息
git show <commit>:<file>    # 查看某次提交中文件的内容

git diff                    # 工作区 vs 暂存区
git diff --staged           # 暂存区 vs 最新提交
git diff <commit1> <commit2>  # 两次提交之间的差异
git diff --name-only        # 仅列出变更文件名
```

## 撤销变更

| 场景 | 命令 |
|------|------|
| 撤销工作区修改（未 add） | `git restore <file>` |
| 撤销暂存区（已 add，未 commit） | `git restore --staged <file>` |
| 撤销最近一次 commit（保留变更） | `git reset --soft HEAD~1` |
| 撤销最近一次 commit（保留工作区，清空暂存区） | `git reset --mixed HEAD~1` |
| 彻底撤销最近一次 commit | `git reset --hard HEAD~1` |
| 安全撤销已推送的 commit | `git revert <commit>` |

### reset 三种模式

```
--soft:   HEAD 回退，暂存区和工作区不变  → 可重新 commit
--mixed:  HEAD 回退，暂存区清空，工作区不变 → 默认模式，需重新 add + commit
--hard:   HEAD 回退，暂存区和工作区全部清空 → 不可恢复，谨慎使用
```

`git revert` 与 `reset` 的关键区别：`revert` 创建新的反向提交来撤销变更，不改写历史，适合已推送的分支；`reset` 直接移动分支指针，适合本地未推送的提交。

## 分支管理

```bash
git branch                  # 列出本地分支
git branch -a               # 列出所有分支（含远程）
git branch <name>           # 创建分支
git branch -d <name>        # 删除已合并的分支
git branch -D <name>        # 强制删除分支（即使未合并）

git switch <branch>         # 切换分支（Git 2.23+）
git switch -c <branch>      # 创建并切换
git checkout <branch>       # 切换分支（传统方式）
git checkout -b <branch>    # 创建并切换（传统方式）
```

`git switch` 和 `git checkout` 的区别：`checkout` 功能过载（切换分支 + 恢复文件），Git 2.23 后拆分为 `switch`（切换分支）和 `restore`（恢复文件），语义更清晰。

## 合并与变基

```bash
git merge <branch>          # 将 branch 合并到当前分支
git merge --no-ff <branch>  # 禁用快进合并，保留分支历史
git merge --squash <branch> # 压缩为一个提交（需再手动 commit）

git rebase <branch>         # 将当前分支变基到 branch 之上
git rebase -i HEAD~3        # 交互式变基最近 3 个提交（合并/重排/编辑）
```

| 操作 | 结果 | 适用场景 |
|------|------|---------|
| `merge` | 创建 merge commit，保留完整分支历史 | 公共分支、多人协作 |
| `rebase` | 重写提交历史，线性、整洁 | 个人分支整理后合并到主线 |
| `squash merge` | 整个分支压为一个 commit | 功能分支合并到主线，保持历史简洁 |

**rebase 黄金法则**：不要对已推送到公共仓库的提交执行 rebase，否则会破坏他人的历史基础。

## 远程协作

```bash
git remote -v                        # 查看远程仓库
git remote add <name> <url>          # 添加远程仓库
git remote remove <name>             # 移除远程引用

git fetch <remote>                   # 下载远程变更但不合并
git fetch --prune                    # 同时清理本地已删除的远程分支引用
git pull <remote> <branch>           # fetch + merge（默认）
git pull --rebase <remote> <branch>  # fetch + rebase（推荐）

git push <remote> <branch>           # 推送分支到远程
git push -u <remote> <branch>        # 推送并设置 upstream
git push --delete <remote> <branch>  # 删除远程分支
git push --force-with-lease          # 安全强制推送（检查远程是否被他人更新）
```

`git pull --rebase` 比默认的 `pull`（fetch+merge）更适合个人分支同步主线——避免无意义的 merge commit，保持历史线性。

## 储藏

```bash
git stash                   # 暂存当前未提交的变更
git stash save "message"    # 带描述信息的储藏
git stash list              # 列出所有储藏
git stash pop               # 恢复最近一次储藏并删除记录
git stash apply             # 恢复最近一次储藏但保留记录
git stash drop              # 删除最近一次储藏
git stash push -p           # 交互式选择部分变更储藏
```

## 标签

```bash
git tag v1.0.0                        # 轻量标签（仅引用 commit）
git tag -a v1.0.0 -m "release v1.0"   # 附注标签（含作者、日期、说明）
git tag -d v1.0.0                     # 删除本地标签
git push --tags                       # 推送所有标签到远程
```

## .gitignore

```bash
# 注释
*.o               # 忽略所有 .o 文件
!main.o           # 排除 main.o（不忽略）
build/            # 忽略 build 目录
*.log             # 忽略所有日志文件
.env              # 忽略环境变量文件
```

规则是逐行匹配的 glob 模式，`!` 开头的行表示排除（不忽略）。`.gitignore` 应被 Git 跟踪；仅限个人的忽略规则放在 `.git/info/exclude` 中。

## 常见工作流

**功能分支开发流程：**

```bash
git switch -c feature/xxx          # 从 main 创建功能分支
# ... 开发、提交 ...
git fetch origin
git rebase origin/main             # 同步主线最新变更
git push -u origin feature/xxx     # 推送并创建 PR
# PR 合并后
git switch main
git pull
git branch -d feature/xxx          # 清理本地分支
```

**紧急修复流程：**

```bash
git switch -c hotfix/urgent main
# ... 修复、测试、提交 ...
git switch main
git merge --no-ff hotfix/urgent
git tag -a v1.0.1 -m "hotfix release"
git push origin main --tags
```

## 常用场景速查

| 场景 | 命令 |
|------|------|
| 忘记加文件到最近一次 commit | `git add <file> && git commit --amend` |
| 撤销某次 commit 但保留变更 | `git reset --soft HEAD~1` |
| 放弃工作区所有未跟踪文件 | `git clean -fd` |
| 查看某行代码是谁写的 | `git blame <file>` 或 `git annotate <file>` |
| 二分查找引入 bug 的 commit | `git bisect start; git bisect bad; git bisect good <commit>` |
| 拣选某次 commit 到当前分支 | `git cherry-pick <commit>` |
| 查看文件在两个分支间的差异 | `git diff branch1..branch2 -- <file>` |
| 查看谁修改了文件的哪些行 | `git blame -L 10,20 <file>` |
| 查看某次 commit 引入了什么文件 | `git diff-tree --no-commit-id -r <commit>` |
| 临时切到其他分支但不提交 | `git stash && git switch other && do_work && git switch - && git stash pop` |
